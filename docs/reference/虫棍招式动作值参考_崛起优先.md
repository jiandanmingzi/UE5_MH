## 读法

- 每个动作值写成“数字（伤害类型，伤害来源）”，例如13（斩击，武器）、15（打击，武器）。
- 伤害类型分**斩击、打击、固定**；来源分**武器、猎虫**。粉尘按猎虫攻击力计算，来源标为猎虫，由招式栏区分粉尘／直接攻击。
- “斩击／打击”表示由猎虫品种决定，**不是同一击同时结算两种伤害**。觉虫击猎虫的固定伤害仍标固定，品种分类写在行名里。
- 加号表示不同命中；×n表示同值重复n次，不把多击合计当作单击MV。动作值保留13、20这样的数值，公式中再/100；肉质仍按0–100保存。
- 有红灯强化版本的动作只列强化值，不收录无红灯对照。红白／三灯攻击力增益、舞踏倍率、属性补正另算，不预乘进基础MV。
- GA列省略共同前缀GA_IG_。来源链接见表内及文末；动画编号不等于原始攻击数据的Hit ID。
- 新增列的单位为**MV／帧**，不是实际伤害：`本行采用的整招参考MV合计 ÷ 本项目从实际Montage入口首帧到DodgeAcceptWindow起点的60FPS等效帧数`。没有闪避窗口时，使用确实开放操作的Handoff或动作结束；细则及动态变量见表后。
- 分子按表中理论全中、未乘舞踏等倍率计算；已匹配的GA现已采用对应基础MV，未匹配招式仍不可据此声称实装。猎虫与武器MV相加只作同权动作值统计，不能据此把两种攻击力来源合并结算实际伤害。

## 项目动作时长与计算口径（2026-10-17）

本列最初为只读文档分析，后续基础MV回填范围见上节，未改变以下计时来源。资产在编辑器关闭时由只读Python Commandlet直接加载核对：19份GA及其实际引用的Montage，解析`DA_IG_Combo`当前有效路线、GA入口覆盖、Section跳转、播放倍率和通知。原始导出及计算证据保存在`Saved/Maintenance/AttackMVPerFrame20261017/`，其中`assets.json`、`routes.json`、`calculations.json`分别记录资产、实际路线和21组固定时长计算。

### 固定时长

- **起点**：本次真正播放的Section首帧，不是资产时间轴最左端；未播放的其他入口不计时。按`EntrySectionByTransitionID → EntrySectionBySourceState → DefaultEntrySection`解析，只列当前Combo表实际能进入的路线。
- **终点**：有`DodgeAcceptWindow`时以其起点为准；不把更早的预输入起点当作操作已开放。本轮二连／飞圆的ComboWindow比闪避窗口略早，仍依本口径用闪避窗口，未改通知。
- **计时**：沿Section真实Next链相加，不直接拿通知全局时间减入口坐标；片段内部已含原序列RateScale／AnimPlayRate，不能再次除2。当前相关Montage RateScale为1，固定GA按1倍播放；正常游戏速度，不计`slomo`、卡肉、命中停顿或输入组合判定等待。
- **单位**：`等效帧数＝实际动作秒数×60`，不额外加1；保留资产的小数帧，不伪装成PIE实测整数输入帧。显示帧数四舍五入至两位，MV／帧由未舍入时长算至四位。
- **上捞额外段**：横扫、反向突进的305入口均确有额外`ConfigIndex=3`攻击窗口，按同一衔接斩参考18计入整招76；308入口没有这次额外窗口，仍为58。四连只列实际接入的两个Entry，各包含一次首击；默认Core不是当前Combo的入招路线，不拿缺首击的Core单独冒充完整四连。
- **突进蓄力**：自然时间轴中Charge占2秒，但运行时可跳过；无反击时`F＝94＋H`，`0≤H≤120`。不能把可选的120帧一律塞进每次施放。
- **放虫／聚爆**：没有闪避窗口的三个施放Montage均为约0.766667秒，即46等效帧。按完成事件开放后续动作计施放成本；飞行、命中和聚爆1秒引爆倒计时可在动作结束后继续，因此这里不是“伤害已经全部发生所需时间”，也不是持续输出DPS。聚爆整次合计一行只用于把原作参考MV归一，不能声称项目采用了原作聚爆公式。

### 空中／条件时长

空中招式不能拿单条动画长度当整招时长：201／380有循环或保持段，操虫斩与觉虫击会按命中切到另一条189。以下F均为从本次GA实际起播开始累计的60FPS等效帧：

- **F189**：到本次189舞踏Montage实际起播的累计帧数，包含此前前摇、蓄力、飞行、命中与切换等待。共用189的`IG Aerial Handoff`在0.750000秒，故再加45帧；0.35秒准备期间189已经在播放，**不得另加21帧重复计时**。操虫斩理论三段全中用60作分子；仅虫命中、落空或提前落地时，应按真正发生的段和实际解除操作限制的时刻重算，不能把主Montage末尾98.1帧当成已经允许再次出手。
- **F203**：到强化操虫穿刺203落地Montage实际起播的累计帧数；其DodgeAcceptWindow在0.750000秒，因此完整三段为`105/(F203＋45)`。高度与循环次数未固定时不填单一数字。
- **F381**：到急袭突刺Over／381实际起播的累计帧数；其DodgeAcceptWindow在1.500000秒，因此完整四段为`113/(F381＋90)`。不把主Montage的69帧单次片长当成所有起跳高度的固定下坠时长。
- 表中均未预乘舞踏。按本项目现行增伤规则，操虫斩完整命中分子可写为`15＋45m`（m为出招快照，猎虫15不乘）；穿刺为`105m`，包括203地面段；急袭为`113m`。觉虫击不加舞踏倍率。m取值以[当前动作设计§6.1](../design/insect-glaive-actions.md#61-舞踏层数)为准，不用下方原游戏倍率说明覆盖项目配置。
- 原作猎虫品种／色数分支尚未在本Demo逐项实现，不能仅用同名JueChongJi的时长给它们标上“本项目实装DPT”。自主猎虫攻击和粉尘自然爆炸无玩家Montage占用，本列标为不适用，而非0伤害。

## 倍率与项目映射注意

1. **操虫斩舞踏阶段：** 出手前已有0／1／2／3次舞踏时，前冲武器段分别乘1.0／1.1／1.2／1.3；命中后上升段分别乘1.1／1.2／1.3／1.3。猎虫段不乘舞踏倍率。首次上升常见33包含倍率，不是另一个基础MV。[S2]
2. **强化操虫穿刺：** 原作接操虫斩舞踏后，一／二／三层另乘1.1／1.2／1.3；不要预乘基础值后再由项目重复乘倍率。[S2]
3. **觉虫击猎虫：** 表中为忽略肉质的原作固定伤害。Demo只有一只猎虫；现行项目规则（2026-10-17）按本次消耗颜色分配：无红灯每击MV15、有红且非三灯MV30、完整三灯MV50；白灯启用贯通，黄灯启用逐次成功伤害产粉。并未实现表中全部原作品种分支；不能擅自选一行套入仍受肉质的通道，声称已还原原作。
4. **粉尘聚爆：** 项目采用用户指定的“两段：数量档位基础伤害＋各团伤害和”，并非原作合计系数的直接复刻。不能把表内整次聚爆合计MV再加上项目逐团贡献，导致重复伤害。聚拢动作本身无伤害。
5. **碰撞窗口与GA索引：** 原作Hit ID、动画序号、GA伤害段索引不是一回事；一个段可能被多个窗口或重复判定使用。已回填范围按实际动作、窗口及去重规则对应；后续扩展仍须逐段核对，不能仅按名字批量覆盖。
6. **无伤害动作：** 仅拔刀、普通收刀／收虫、空回、撑杆跳、普通下落／落地本身没有需回填的攻击段。普通收虫不是原作铁虫丝技“猎虫回归”，不能套用另一招的伤害。
7. **范围边界：** 不因只有导入动画就加入降龙、铁虫丝跳跃、猎虫滑翔等。冰原急袭额外猎虫穿刺尚未核定完整映射，不用含糊的Kinsect Charge条目代填；操虫斩原表另有下落接触定义，也不据此给项目三段方案自动补第四击。
