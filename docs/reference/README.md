## 五个必须记住的口径（每一条都踩过）

### 1. 向上轴是 **Y**，不是 Z；单位是**米 / m·s⁻¹**

`Scripts/MHRise/README.md` 明写。水平面 XZ。位置是米、速度是 m/s，项目用厘米 ⇒ 派生表已 ×100。`world_x`/`world_z` 是**地图世界坐标**（−500 量级），只有差值有意义。

### 2. 采样率 **119.8 Hz**，**帧数 = 样本数 − 1**

不是 50 Hz。154 跑满 195 样本 = 194 帧 = 1.620 s。**每招式按 120 Hz 折算帧数。**

### 3. 43 份录制里有 **7 份不能用**（可用 36 份）

`20260912_210326_01`、`_210721_02`、`_220353_01`、`_220449_02`、`_224230_01`、`_230951_01`、`_231037_02` —— 它们是 14 列 / 45 列的**老格式，没有 `player_motion_old_id` 列**。第一版生成器把它们当 id 为空的段写了 1600 余行噪声，别再犯。

### 4. 分段依据是 `player_motion_old_id`，**不是** `motion_l0_id`

后者长期恒为 1。核对过：`160 → 154 → 137` = 突进回旋斩 → 舞踏 → 空中回避。

### 5. **id 是按表分配的，不同表都从 0 开始** ⇒ 编号不全局唯一

一个 id 在录制里出现、却不在 `虫棍招式表.md` 里，**不能推断它不是虫棍的动作** —— 也可能是另一张表（如武器无关的大硬直）里撞号的 id。**「查不到就剔除」这条推理是错的。**
同理，**小硬直（`400–404`、`411/412`）空中不能触发**，所以它们不可能是空中被打断的后继；**大硬直是武器无关的，不在虫棍表里**。

## 真值表怎么读

### 「跑满段」= 帧数众数簇里**最靠右**的那一箱 —— 三条都是踩出来的

**判据**：把**帧数**（不是秒）按 **6 帧**分箱，**占比 ≥30% 的箱中最靠右的那个** ⇒ 定长招式，跑满段 = 该箱。

- **不能**用「时长 ≥ 最大值 ×0.98」—— 对**时长由玩家决定**的招式（`160` 突进回旋斩、`4` 持续奔跑）会把一个孤例当自然长度。这条错规则曾把 `160` 报成「2.393 s 恒定」，进而把舞踏的蒙太奇时间算成 2.709 s（真值 0.316）。
- **为什么要「最靠右」而不是「最常见」**：玩家**越认真探一个招式，它的提前取消样本就越多**，取消簇迟早盖过自然簇，"最常见箱"于是把自然长度定成取消长度、候选集变空、数字凭空消失。实测 `154` 舞踏：194 帧（自然玩完）28 次 vs 38 帧（最早取消）24 次 —— 取消簇以 32:31 一票之差赢下众数，舞踏就从第二节彻底消失了。取消只会比自然长度**更短**，所以取最靠右的合格箱。
- **为什么按帧数分箱**：采样间隔在 0.0077–0.0093 抖动，全库还有 6 处 >50 ms 卡帧。实测一个 **112 帧**的 `147` 段因 0.178 s 卡帧，壁钟被抬到 **1.093 s**，按秒分箱时会和 **131 帧**的众数簇落进同一箱、把自己的后继并进「自然后继」。6 帧正好对齐采样网格（0.05 s = 5.99 帧）。
- 占比不足 ⇒ 标为**变长**，**不存在「自然长度」**，表里那一格留 `—`（不能拿中位数冒充配置值）。它们的可操作情况见真值表第四节左尾分布。
- **录制首尾段与卡帧段不参与判定**：见下面「边界段」一条。

### 旁挂一列「最长观测」（不一致时标 ⚠）

众数簇是**最常见**的长度，不是**自然**长度。被外部事件砍断的招式两者会分家 ——
`159` 众数簇 1.486 s，最长观测 1.597 s 且那一次后继是 `157`：**1.486 是被触地砍断的**，自然长度约 1.596（招式表已记，生成器独立复现了这条）。⚠ 就是自动挑出这种情况。

### 只能取「完整观测」：录制首尾段 **一定**是假的取消

每份录制的**最后一段**没有下一段 ⇒ `next_id = None`，而 `None not in 自然后继集合` 恒真 ⇒ 它会被**无条件判成「玩家主动取消」**，可它的长度只是「按 F9 之前还剩多久」。**36/36 份录制全部中招**，其中最狠的是 `148` 的 **14 帧**（加边界保护后变 21，再把受击排除掉才是真值 **47 帧**）。首段同理（被录制起点截断）。⇒ `is_boundary`，既不进众数簇也不作候选。

同类：段内相邻样本间隔超过中位间隔 3 倍且 >30 ms 的**卡帧段**（`has_hitch`），帧数与壁钟脱钩，同样两边都不用。

### 最早可操作帧：**除受击/失控外，后继是什么动作都可以当探针**

（2026-09-19 订正，旧口径只认后继为 `137` 空中回避。旧口径的硬伤：**用空中回避当唯一探针，就永远测不出空中回避自己的最早可操作帧**；而且「可操作」不该依赖某一个特定后继动作。）

- **候选段** = **严格短于任何跑满段帧数**的段 —— 判据只凭「短」，不看后继 id 在不在自然后继集合里。后者有两个毛病：会把「玩家拖着没按」的长段当成取消（实测 19 个有候选的招式里 7 个如此），又会把「提前取消到同一个自然后继」的真取消静默丢掉。**最早可操作帧只藏在候选段里。**
- **可信度按「取消进了哪个动作 id」判，不按样本量判**（用户口径）：「16 帧处取消进空中回避」哪怕只观测到一次也可信；「取消进受击」哪怕一百次也无意义。所以表里给**同帧次数**与**次早差几帧**作信息，**不设**「样本不足 ⇒ 未测定」门槛。
- 「该刻抬升/水平」= 候选段**末帧**相对段首的位移 —— 段在被取消那帧结束，末帧就是可操作那一刻（**不是该段的 apex**）。
- **蒙太奇** = 前置段帧数 + 该段最早帧数，**但仅当前置段属于同一蒙太奇**。后撑杆跳的蒙太奇从跳段 `146`/`158` 开始（恒定），所以要加；舞踏的蒙太奇从 `154` 自己开始（前置 `160` 是另一段招式且长度不恒定），所以加 `*` 标记「此项有人工判断」。
- **第三节的「各后继各自的最早」是给「通用可操作帧」做检验用的**：判据先写死 —— 若存在通用帧，**同一状态层内**所有合法后继的最小帧数应**完全相等**。实测 `148 起跳落地` 的 **`104`/`118`/`141`/`145`/`155` 五个**后继最早**全是 50 帧**（支持通用帧；另有 `160` 一次 47 帧的孤点），而 `147` 是 `137` 16 帧 vs `186` 51 帧（逐后继门槛）。必须**按状态分层**比，地面动作接不了空中动作。
  > 这条判据**是在排除掉受击之后才干净的**：`148` 原本报「最早 21 帧」，而那 21 帧是「取消进 `21`（受击）」—— 受击一排除就变成 47 帧，正好落回 50 附近。判据和排除集是互相成全的。

### 受击/失控排除集：**按「进入那一帧有没有瞬时速度跳变」判，不看名字也不看扇入**

`CONTROL_LOSS_IDS = {15, 21, 30, 33, 452, 453}`（击飞）+ `{57, 58, 456}`（硬直）。

**判据只有一条**：动画流的速度是连续的，一帧内蹦起来只能是外力。这条判据**不依赖命名、不依赖招式表**，因此不受「id 按表分配、不同表撞号」的影响。

**击飞链**（两次独立观测都指向同一个固定冲量：**水平 485 cm/s + 垂直 600 cm/s**，方向 = **受击瞬间朝向的 ±1 倍** ⇒ 只有两个变体、能 100% 二分开，不存在连续的受击角度）：

| | 朝**后**飞（来向=正面） | 朝**前**飞（来向=背后） |
|---|---|---|
| ① 击飞 | `15`（90–103 帧，中位 398 cm，发射方向 ±180.0°） | `21`（94–102 帧，384 cm，**0.0°**） |
| ② 空中坠落（仅空中受击） | `30`（19–25 帧） | `33`（24 帧） |
| ③ 落地翻滚 | `16`（**118 帧 / 668.4 cm**） | `22`（**118 帧 / 616.6 cm**） |
| ④ 跪地起身 | `452` | `453` |

**全库零反例**：进入 `15`/`21` 那一帧 Δvy 中位 **+587 / +602**；`15` 后继只有 `16`(53)/`30`(14)，`21` 只有 `22`(9)/`33`(1)；`452` 前驱 **58/58 = `16`**，`453` 前驱 **9/9 = `22`**。

**空地问题的答案：不是两套动作，只是多插一段。** 中括号里的 `30`/`33` **只在空中被打中时出现**：地面受击高度 **9.6–65.6 cm**、空中 **143.5–273.6 cm**，中间是干净断层，两边都 100%。物理解释是坠落时间长短 —— `15` 的动画播完人还在空中，游戏切到「下坠」动画（`30` 与 `15` 末帧速度**连续**，不是新冲量），落到地面再进 `16`。起手段、翻滚段、起身段三套完全相同。

**硬直链 `57 → 58 → 456` 与击飞不是一回事**：进入 `57` 时 Δvy≈0、速度被**清零**到 ~90 cm/s，恒 176 帧（1.469 s）、位移 41 cm、只在地面。前驱窄（`160` 17/18）。

**`16` / `22` 为什么没收进集合**：这两个 id **重载**。链上的 `16` 是 118 帧 / 668.4 cm 的受击翻滚，另有 6 段 `16` 是 30–90 帧 / 70–170 cm 的**起步过渡**（前驱 `4`/`6`，后继常是 `160`）；`22` 同理（链外 1 段 56 帧）。按 id 一刀切会误伤那几段，所以宁可少收。

**四条踩过的错，别再回头：**

1. 招式表里那批名字（`400–404`/`411/412`/`414`/`450–463`）**整库一次都没出现过**，加进去是不可证伪的空转。**不能反推「没挨过打」** —— id 是按表分配的、不同表都从 0 开始，撞号的动作不会出现在虫棍表里。
2. **「扇入判据」已被数据否掉**：受击应当扇入大，但 `137` 空中回避（合法可控）扇入 **6** / 最大前驱占比 53%，而 `57` 扇入只有 **2** / 占比 94%。（`15` 的 15 种前驱**确实**是受击的签名之一，但只是签名，不是判据。）
3. **`452 受伤跪地后的站起` 当初被当成「命名可疑、扇入 1」而差点删掉** —— 实测它就是击飞链的第四段。**照名单删会误删 58 段真数据。**
4. 受击那一帧**朝向本身会跳 ±10°**（最大 68°），所以「前/后」是相对**受击后**朝向判的。现有数据分不清「按朝向取前后标志」和「算出攻击者方位再把猎人转过去」—— 两者观测等价，实现时按前者做即可。

`186` 的旧「存疑」已结案：它是 **空中操虫斩**（12/12 恒 86 帧、逐帧位冻结、后继恒 `187`、悬停期间动画在播且朝向可转）。

### 四条跨链的口径（2026-09-19 补录后加）

**0. 重力不是全局的，是「每个状态一条」，而且下落段不设重力、继承发起动作。**
完整实测见 **`下落物理.md`**。要点：`137` 空中回避 = 纯抛体（g = **−2378 cm/s²**，R² = 0.999，
与 `AerialFallGravityScale = 2.4246` 差 0.08%）；`142` 弧 = −2397 / `156` 白灯弧 = −2517
（正好是项目那两个常数）；`188` 操虫斩未击中 = **−3101（3.16 g₀，配置里没有这个值）**；
击飞链 = −1580、舞踏 = −1803。**`137`→`157`→落地是同一条抛物线**（152/152 例 R²>0.99），
所以别给下落段单独配重力。

**1. 惯性会原样继承到「动作结束后的下落」，唯一的重置点是触地。**
判据写死：**后继首帧速度 ÷ 前驱末帧速度**。

| 链 | n | 比值中位 | 判定 |
|---|---:|---:|---|
| `137` 空中回避 → `157` 下坠 | 57 | **0.989** | 继承 |
| `187` 操虫斩前冲 → `188` 未击中 | 61 | **0.991** | 继承 |
| `137` → `148` 落地（对照） | 33 | **0.373** | 清零（末帧 898 → 首帧 **338 cm/s**，与入速无关） |

所以「往前跳再往前回避能回避更远」不成立（空回位移恒 1065 cm），但**回避/突进之后的
下落会把那份速度原封不动带走**，直到触地。

**2. 操虫斩的瞄准只有在玩家按住 RT 时才生效。**（用户实测的机制；遥测里**没有按键状态列**）
不按 RT 时突进**恒为水平** —— 逐帧 `velocity_y` **精确等于 0.0**（位移 721 / −26 / 722 cm）。
所以数据里只能看到「跟随 / 不跟随」两种结果、看不到原因；判断某条样本属哪类，
**只能看它跟不跟随**（判据：`|突进俯仰| ≤ 1°` 且 `|相机俯仰| ≥ 5°`）。全库 106 条里
99 条跟随、7 条未瞄准 —— 后者集中在 `20260919_194059_01`（6 条），是**「未瞄准操虫斩」的参照**。

**3. 镜头朝向的符号要**几何自检**，不要按文件名硬编码。** 判据：`dot(cam_forward, 相机→猎人)`
应当 ≈ **+1**（相机在猎人后方、看向猎人）；`< 0` 就是反的（录制器 1.7.0 的缺陷）。
全库只有 `20260919_005435_01` 是 **−0.968**，其余 42 份都是 +0.96~+0.98。
这个方法比「记住是哪一份录制」可靠 —— 以后换录制器版本也不用改。

## 关于「能不能做成曲线」

**能。`UCurveVector` 就是三维的**（时间 → FVector，X/Y/Z 各一条 `FRichCurve`），一条装位置、一条装速度；2 s × 120 Hz ≈ 240 关键帧对曲线资产是很小的量。

**装不下的三类**，这才是不能硬塞的理由：

1. **每样本超过 3 个数**：招式元数据（总时长、最高点、蒙太奇时刻、最早可操作帧）—— 留在标量表里。
2. **旋转**是 4 个数（四元数）—— 要 `UCurveQuat`，或拆成欧拉角。
3. **同一招式的多次录制**：曲线是**单值函数**。真值表的价值恰恰在保留离散（最短的那条 = 最早可操作帧，跑满的那条 = 顶点），所以标量表必须是多行/多值，不能只留一条曲线。

**落点**：曲线是 uasset，属于 `Content/`，不属于 `docs/`。项目现状：`UCurveVector` **只被运行时 `NewObject` 用过**（`MHGZBackVaultAbility.cpp:908`），`Content/` 下**零个曲线资产**，也**没有** JSON→资产的管线。要烘资产，最短路径是照抄 `MHGZWuTaMontageSetupCommandlet` 的骨架（`CreatePackage` + `NewObject` + 现成的 `AddLinearKey` + `SaveAsset`）。

**⚠ 消费方约束**：`FWeaponMovementRequest::PathOffsetCurve`（`MHGZWeaponRuntimeTypes.h:623-629`）要求 X 沿 `DirectionSnapshot`、**起止偏移都为零**。所以**不能把录制原样烘进去**，得先减掉线性分量做归一化（`MHGZBackVaultAbility.cpp:965-971` 就是这套变换）。
