# M4.2.1 收刀 Run/Sprint Loop 候选库重设计

> **状态（2026-09-02）：设计已冻结，尚未实施。** 本文替代已经完整回退的“`GaitChangeSerial` + `ForceInterruptAndInvalidateContinuingPose` + 全节点 Blend 原子配置”试验。实施前必须以本文为准；旧方案不可恢复。

## 1. 任务边界

本切片只解决：**收刀状态、已经进入 Run 或 Sprint Loop、摇杆保持有效时的 Run <-> Sprint 改挡。**

- 仍由 Motion Matching 在允许的循环动画中选具体帧；不改为状态机直接播放。
- 初始起步、真实松杆 Stop、Walk、持刀移动、攻击/收刀/翻滚的 Action Exit 全部保持原合同。
- Walk <-> Run 暂不纳入本切片。当前没有“Walk Loop 与 Run Loop 的相位兼容”或专用桥接资源的审计证据；它继续走已签收的完整 `PSD_MH_Shth_Move`，以后作为独立资产审计项处理。
- 这不是调整 `MM_Intent`、`MM_MoveGait` 权重的任务，也不是调整 `DesiredSpeed` 或制造输入死区的任务。

## 2. 录制证据与根因

证据目录：`Saved/RuntimeTelemetry/20260902-141958-BP_IG_Character_C_0-53873`。

### 2.1 当前全量库的组成

`PSD_MH_Shth_Move` 当前有 16 个条目：Idle、Walk/Run/Sprint Start、Walk/Run/Sprint Loop，以及所有已签收 Generated Stop。它的 `ContinuingPoseCostBias=-0.05`，并包含 Start/Stop 的 `PoseSearchBlockTransition` 元数据。

因此，它是 Start/Stop 生命周期的正式候选库；它不适合作为“巡航改挡时只允许两个 Loop 竞争”的候选语境。

### 2.2 Run -> Sprint 的实际失败链

在记录帧 `11425`（记录时间 `83.711723s`），输入保持满推且 RB 已按下，`MM_MoveGait` 从 Run 改为 Sprint。

1. 候选前十名全是 `AS_Shth_Sprint_Start`，最低总成本为 `0.074534`。
2. 这些候选全部带 `DiscardedBlockTransition`，因此不能胜出；这是 Start 的正确保护，不能删除。
3. 当帧实际重搜仍选回 `AS_Shth_Run_Loop`，总成本为 `0.2945`。
4. 到帧 `11441` 才选中 `AS_Shth_Sprint_Loop_125x`，延迟约 `0.133s`；同一录制中还存在最高约 96 帧的改挡延迟。

这说明根因不是“Continuing 没有被打断”或“`MM_MoveGait` 权重太低”。先前试验即使强制撤销 Continuing，也只是让全量库重新搜索后仍回到 Run。真正的问题是：**全量库在巡航改挡时同时暴露了不应进入的 Start/Stop 候选；最优 Sprint Start 又被正确的 BlockTransition 拒绝。**

### 2.3 UE5.6 的可用中断语义

UE5.6 `EPoseSearchInterruptMode::InterruptOnDatabaseChangeAndInvalidateContinuingPose` 只在“当前结果所属数据库不再位于新的可搜索数据库列表”时中断；`ForceInterruptAndInvalidateContinuingPose` 则无条件中断。

新设计只能使用前者：候选集实际改变时，旧数据库已经不再合法，才让引擎重建查询。不得恢复任何 Serial、每帧 Force、或“输入值变了就强制撤销 Continuing”的逻辑。

## 3. 冻结的候选库设计

### 3.1 三个收刀候选语境

| 语境 | PSD | 允许的动画 | 所有者 |
|---|---|---|---|
| FullMove | `PSD_MH_Shth_Move`（既有） | Idle、全部 Start/Loop、全部 Stop | 已签收的 M4.2 Stop/Start 合同 |
| RunLoopOnly | `PSD_MH_Shth_Run_LoopOnly`（新） | `AS_Shth_Run_Loop` 唯一条目 | 本切片的 Run 巡航 |
| SprintLoopOnly | `PSD_MH_Shth_Sprint_LoopOnly`（新） | `AS_Shth_Sprint_Loop_125x` 唯一条目 | 本切片的 Sprint 巡航 |

两个新 PSD 都使用当前 `PSS_MH_Move`、60Hz 索引和原动画的曲线；每个 PSD 只有一条 Loop，**不得**复制 Idle、Start、Stop、Generated Stop，也不得添加 `PoseSearchBlockTransition`。它们不是新的动画，也不修改原动画、Root Motion、播放倍率或 PSS 权重。

新 PSD 的初始配置从 `PSD_MH_Shth_Move` 复制：`PoseSearchMode`、`ContinuingPoseCostBias=-0.05`、`LoopingCostBias=0`、`ExcludeFromDatabaseParameters=[0,0]`、`DisableReselection=true`。唯一变化是条目集合。

### 3.2 运行时候选集选择

新增私有枚举 `EMHGZMMNormalMoveCandidateSet`：`FullMove`、`RunLoopOnly`、`SprintLoopOnly`，并为每个 MM 节点保存当前已提交的候选集。它只记录“下一次搜索允许哪些 PSD”，不是输出姿势状态机，也不保存播放时间；该快照用于避免从 Start/FullMove 首次进入同档 Loop 时制造一次无意义的跨数据库重搜。

`RouteMotionMatchingPreSearch` 在现有 Action Exit 分支已经返回之后，按以下优先级决定收刀普通移动节点的候选集：

```text
ActionExitRoute != Move
  -> 完全保留 M4.5 原逻辑；将普通候选集快照复位为 FullMove，本切片不介入

没有有效移动输入 / bMMStopRequestActive / bStartQueryActive
  -> FullMove

最新真实 MM 获选结果不是 RunLoop 或 SprintLoop
  -> FullMove

当前已提交集合为 RunLoopOnly 或 SprintLoopOnly，且目标档位仍为 Run/Sprint
  -> 保持或切到目标对应的 LoopOnly

当前已提交集合为 FullMove，最新真实获选结果为 RunLoop 或 SprintLoop，且目标档位与该实际 Loop Family 不同
  -> 切到目标对应的 LoopOnly

其余情况（包括首次进入同档 Loop、Walk 目标）
  -> FullMove
```

“最新真实获选结果”必须通过 `FPoseSearchBlueprintResult.SelectedAnim` 或已经排队的 `FMotionMatchingSelectionEvent` 的对象引用识别，不得根据动画时长、字符串包含关系或预测速度猜测。目标档位必须在 `NativeUpdateAnimation` 中从当前有效输入与现有 `TargetSpeed` 计算为私有 `EMHGZStopGait` 快照；不得使用 `DesiredSpeed`。

### 3.3 唯一合法的数据库切换

对 `FullMove` 使用：

```cpp
ResetDatabasesToSearch(Node,
    EPoseSearchInterruptMode::InterruptOnDatabaseChangeAndInvalidateContinuingPose);
```

对两个 LoopOnly 集合使用：

```cpp
SetDatabaseToSearch(Node, DesiredLoopDatabase,
    EPoseSearchInterruptMode::InterruptOnDatabaseChangeAndInvalidateContinuingPose);
```

该调用每帧可以重申当前候选集，但 UE5.6 只会在当前结果数据库不属于该集合时中断。首次从 Start/FullMove 进入同档 Loop 时仍停在 FullMove；只有已经巡航且目标 Family 真正不同，才进入 LoopOnly。因此：

- RunLoopOnly -> SprintLoopOnly：Run 的数据库不在 Sprint 集合中，发生一次合法重搜；只能从 Sprint Loop 的合法帧中选择。
- SprintLoopOnly -> RunLoopOnly：同理。
- LoopOnly -> FullMove（真实松杆）：LoopOnly 数据库不在 FullMove 中，发生一次合法重搜；原有 Stop 查询和 `MM_StopGait` 锁存照常工作。
- 在同一候选集内：Continuing 完整保留，没有“每帧重搜”。

不得调用 `ForceInterrupt*`；不得新增 `GaitChangeSerial`、Consumed Serial、全局 Start/Stop 重置或额外 Force-Idle。

### 3.4 为什么它能解决本次延迟

Run -> Sprint 时，搜索集合将从“包含 Sprint Start 且必须被 BlockTransition 拒绝的 16 条全量库”变为“仅包含 Sprint Loop”。于是 `AS_Shth_Sprint_Start` 根本不会进入候选表，`BlockTransition` 继续只保护真正的 Start/Stop 生命周期；Pose、Trajectory 仍决定 Sprint Loop 内的具体相位帧。

该方案只在 Run/Sprint 的同相循环资源之间启用。已审计信息表明二者的循环起点/终点均为右脚着地、两腿并列、左脚准备迈步；仍由 PSS 的双脚 Pose、轨迹和短 Blend 选择实际落点，不硬编码 `0.125s` 跳帧。

## 4. 实施分工与顺序

### E4.2.1-1：可脚本审计的候选 PSD

以 Editor Commandlet 创建/更新两个 PSD；不要求手工拖拽。

1. 创建 `PSD_MH_Shth_Run_LoopOnly` 与 `PSD_MH_Shth_Sprint_LoopOnly`，均位于既有 MotionMatching 目录。
2. 复制 FullMove 的 Schema 和数据库级设置，只填入规定的一条 Sequence。
3. 保存、建索引，随后运行专用审计：Schema=32 维 / 60Hz；每库恰有一条正确 Loop；无 Start/Stop/Idle/Exit；`MM_Intent=0`、`MM_DistanceToStop=0`、`MM_StopGait=0`；保留对应 `MM_MoveGait`；无 `BlockTransition`。
4. 不修改 `PSD_MH_Shth_Move`、`PSD_MH_UnSh_Move`、PSS、Generated Stop、ABP 节点 Blend 配置或任何动画序列。

### M4.2.1-1：运行时路由与自动化

修改范围限于 `UMHGZMotionMatchingAnimInstance`、其纯数学/自动化测试和 Telemetry CSV 字段。

1. 加载两个新 LoopOnly PSD，并在加载失败时以明确日志失败；不能静默退回错误候选库。
2. 新增候选集枚举、每节点当前候选集快照、收刀目标档位快照，以及“精确识别 Run/Sprint Loop 获选结果”的对象级帮助函数。
3. 将普通 `Move` 分支从无条件 `ResetDatabasesToSearch(...DoNotInterrupt)` 改为上述候选集路由；进入非 `Move` 的 ActionExit/ActionIdle、姿态切换、输入 Start/Stop 或时序重置时都清除 LoopOnly 快照。ActionExit、ActionIdle 和持刀节点的数据库路由保持原路径。
4. 仅在 CSV `MotionMatching/Query.csv` 增加 `SheathedCandidateSet`、`SheathedTargetGait`；不删除既有列。
5. 增加 `MHGZ.M4.2.1.LoopCandidateRouting` 自动化，覆盖：Run/Sprint Loop 互切、Start/Stop/Walk 回 FullMove、ActionExit 不介入、同一数据库不请求中断。

### M4.2.1-2：构建与录制验收

1. Development Editor 编译和所有既有 `MHGZ.PMM.Query` 测试必须通过。
2. 新路由自动化与 LoopOnly 资产审计全绿。
3. 录制时开启 `mhgz.Telemetry.Enable 1` 和 `mhgz.Telemetry.PoseSearchDetail 1`；导出候选 CSV。
4. 从 Run Loop 的至少四个循环相位按下/松开 RB：首个进入目标候选集的搜索不得包含任何 Start/Stop；目标 Loop 最迟在两个动画更新帧内胜出。
5. 每种 RB 状态真实松杆：只发生一次对应 `MM_StopGait` 的 Stop；不得回归 Walk 抢 Run Stop、二次 Stop 或 Stop 抽搐。
6. 在 Start 期间按/松 RB：仍保持 FullMove，不能进入 LoopOnly，不能打断已签收的第一步承诺。
7. 回归 E4.2/M4.5：移动收刀、收刀/持刀前滚、拔刀和突刺的 Exit->Move、Exit->Stop、ActionIdle 不变。

## 5. Blend 与后续范围

本轮**不修改**两个 Motion Matching 节点的 Blend 参数。恢复后的基线为：收刀节点 `BlendTime=0.05s`、非惯性、`MaxActiveBlends=1`；持刀节点维持当前资产值。先确认正确候选集能在目标帧切换，再单独记录可复现的视觉接缝，才允许做一个小范围 Blend 实验。

Walk <-> Run、资源缺失的 GaitTransition、以及未来落地/功能动作 Exit 的候选库属于后续独立切片。它们不能借用本切片的 Run/Sprint 资源兼容性，也不能回填进 M4.5 已签收的 Action Exit 合同。
