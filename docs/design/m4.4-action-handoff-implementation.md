# M4.4 动作退出与根运动交接：详细设计及实施记录

> 状态（2026-08-31）：**M4.4 C++ 合同与 E4.2 的 Exit / ActionIdle 路由均已自动接线、编译、保存并审计；当前只等待 M4.5 PIE 固定矩阵。** 本文只定义通用运行时接口，不授权创建新地面招式、Entry Section、Combo 分支或 E4.3 批量资产。

## 1. 目的与边界

M4.2 已签收普通移动和真实松杆 Stop；它不能负责功能 GA 末帧直接进入普通 Move PSD。Telemetry 已证明该做法会让无输入时的 Loop 因姿势成本胜过 Idle，或把动作残余误读为 Stop。

M4.4 的唯一目的，是为“功能部分已经完成、但需要由 Motion Matching 消化退出尾段”的路径建立同一份合同：

```text
功能 Montage（ActionToken 所有）
  -> Action Root Motion Phase（真实根位移 / 可选移动输入观察）
  -> 无功能安全段
  -> Motion Matching Handoff（原子发布 + 精确释放 owner）
  -> E4.2 AnimBP Exit PSD router 选择候选库
  -> ExitTransition 自然交给普通 Move PSD 的 Loop / Stop / Idle
```

它不直接播放任何 Sequence，不把完整 Montage 放进普通 PSD，也不以强制 Idle、输入死区或改低 `MM_Intent` 权重掩盖错误候选。

## 2. 已落地的运行时接口

| 组件 | 文件 | 责任 |
|---|---|---|
| `EMHGZMotionMatchingHandoffType`、`FWeaponMotionMatchingHandoff` | `WeaponRuntime/MHGZWeaponRuntimeTypes.h` | 定义退出候选**族**：`SheatheMoveExit`、`DodgeMoveExit`、`DrawExit`、`AttackExit`；从不指定具体动画。 |
| `UMHGZWeaponRuntimeHostComponent` | `WeaponRuntime/MHGZWeaponRuntimeHostComponent.*` | 发布、读取、按 Serial 精确消费 Handoff；运行时重建或新功能 Action 会清除旧 payload。 |
| `UAnimNotifyState_ActionRootMotionPhase` | `ActionSystem/AnimNotifyState_ActionRootMotionPhase.*` | 按 UE 提供的 `(Mesh, MontageInstanceID)` 解析当前 ActionToken；标记根运动阶段并可记录 Raw Stick。 |
| `UAnimNotify_MotionMatchingHandoff` | `ActionSystem/AnimNotify_MotionMatchingHandoff.*` | 安全帧中按同一精确 Token 请求 Handoff；绝不扫描全局 Active Ability。 |
| `UMHGZGameplayAbility` | `ActionSystem/MHGZGameplayAbility.*` | 保存每次 Action 的 Phase 状态，检查类型/Commit/所有权，并执行原子交接。 |
| `UMHGZMotionMatchingAnimInstance` | `Animation/MHGZMotionMatchingAnimInstance.*` | 把 Host payload 暴露给 AnimBP 的 Exit PSD router，并写入 Telemetry；线程安全图回调只入队 serial，由 `NativeUpdateAnimation` 再按 serial 消费 Host payload；不在 C++ 中选动画。 |

### 2.1 由 GA 资产显式允许的出口

每个有资格接 E4.2 的 GA 在 `Ability | Motion Matching | Allowed Motion Matching Handoff Types` 中显式声明允许的 `HandoffType`。默认空数组。

因此以下情况均安全失败：Notify 放错 Montage、Notify 被复制到未审计 GA、类型与 GA 不匹配、Token 已过期、Action 已结束。失败不会发布 payload、不会结束 GA、不会释放其他 Action 的 Root Motion owner。

有独立玩法 Commit 的基类还会加门：

- `UMHGZSheatheAbility` 必须已经 `SheatheCommit`；
- `UMHGZDrawAttackAbility` 必须已经 `DrawCommit`；
- 普通攻击、Dodge 的后续“没有玩法 Notify”由 E4.2 审计保证，不能仅凭代码猜测。

## 3. Root Motion Phase 合同

`Action Root Motion Phase` 有两个独立开关：

| 设置 | 用途 |
|---|---|
| `bOwnsMontageRootMotion = true` | 只覆盖真实 Montage Root Motion 段；开始时当前 Token 获得独占 owner。 |
| `bOwnsMontageRootMotion = false` | in-place 段；不制造 Root Motion owner。可用于移动退出尾段的输入观察。 |
| `bObserveRawMovementInput = true` | 记录物理摇杆，不读取 `bHasInput`，所以不受 `Combat.State.BlockMovement` 影响。 |

Phase Begin/Tick/End 都使用 Notify 的精确 ActionToken。记录项为：当前 Raw Stick、是否曾有有效原始移动输入、该输入之后是否发生过下降沿。

**Phase End 不立即释放 owner。** 它只证明“之后已没有该阶段声明的根位移”；owner 保留到 Handoff 成功。这使得缺失、错放、Commit 未完成的 Handoff 仍保留原 Montage 的兼容所有权，不会产生一帧 Root Motion 空档。

## 4. `Motion Matching Handoff` 的原子流程

Notify 调 `UMHGZGameplayAbility::HandleMotionMatchingHandoff` 后，必须按以下顺序全部成立：

1. Token 就是当前活跃且已 Commit 的 Action；
2. GA 显式允许该 `HandoffType`；
3. 至少出现过一个 Phase，且没有仍在开启的 Phase；
4. GA 的专属玩法 Commit 已完成；
5. RuntimeHost 没有其他 Action 的 Montage Root Motion owner；
6. 若当前 Token 仍拥有 owner：释放**该 Token**；若发布失败，立即重新获取同一 owner；
7. Host 写入新的、单调 `Serial` payload；
8. 正常结束源 GA，使 AbilityTask 按其已有规则 Blend Out 原 Montage。

第 6～8 步构成成功交接。失败停在原路径，且绝不以 Tag、Character 变量或 `bMMForceIdle` 时间保持作为旁路。

### 4.1 Handoff payload

`FWeaponMotionMatchingHandoff` 包含：

- `Type`、`Serial`、`ActivationSequenceID`；
- Handoff 瞬间的 `RawMoveInput` 与当前是否仍有 Raw Input；
- 可移动 Phase 内是否曾推杆；
- 可移动 Phase 内是否曾推杆后松杆；
- `bPendingStopAtHandoff`：仅“曾推杆、之后松杆、交接瞬间仍无输入”时为真。

AnimBP 的 `On Motion Matching State Updated` 在 Exit PSD 已成功设入节点后调用 `QueueMotionMatchingHandoffConsumption(Serial)`。该线程安全调用只入队；下一次 `NativeUpdateAnimation` 再调用 Host 的 `ClearPendingMotionMatchingHandoff(Serial)`。因此旧图更新无法清掉同一帧后发布的新 payload，也不会从动画线程写 RuntimeHost。新功能 Action 注册时仍会作废尚未被消费的旧 payload，避免旧退出尾段路由新动作。

## 5. AnimBP 与 Telemetry 接口

`UMHGZMotionMatchingAnimInstance` 已公开以下只读变量，E4.2 的 Exit PSD router/图接线只读取它们：

- `bMMHandoffActive`、`MMHandoffType`、`MMHandoffSerial`；
- `MMHandoffRawMoveInput`、`bMMHandoffHasRawMoveInput`；
- `bMMHandoffHadRawMoveInputInMobilePhase`、`bMMPendingStopAtHandoff`。

它们不会改写现有 `MMIntentQuery`、`MMMoveGaitQuery`、`MMDistanceToStopQuery` 或 M4.2 Stop 生命周期。E4.2 另公开 `bMMHasLocomotionInput`、`bMMExitWantsMoveDatabase`、`bMMRouteSheathedActionIdle`、`bMMRouteUnsheathedActionIdle` 与 `MMActionIdleContextSerial`：前两者只决定候选集何时允许回到普通 Move PSD；后两者把无输入、无移动 Handoff 的动作导入 stance 专用的 Idle-only PSD。它们都不选择具体 Sequence。

`Animation/Playback.csv` 已新增 Handoff 字段，可在 PIE 中确认：先有 Montage owner，再出现当前 Serial，随后 owner 释放；不会有两者同时提供根位移。`MotionMatching/Query.csv` 可同时核对 ActionIdle context、真实输入与 Exit 的候选集意图。

## 6. E4.2 必须在编辑器完成的工作

此轮的三个移动 Exit 仍仅为移动收刀 Walk 与两条前向翻滚 `MoveExit`。`AM_IG_TuCi` 与拔刀攻击没有审计通过的无功能尾段，因此仍不接入 Handoff Exit PSD；它们在无输入结束时只切入 ActionIdle PSD，不被伪装成 ExitTransition。`ABP_MH_Character` 的两个回调、ActionIdle PSD 与输入感知尾段路由已由 `MHGZE4ActionIdleRouting` 自动完成。

每条路径必须：

1. 审计每个 Section 的 Root Motion、曲线、玩法 Notify；
2. 确认或裁出无功能 `ExitTransition`：完整保留源动画 Root Track（首帧平移、旋转、缩放及后续真实 Root Motion）；不得强制重基为 identity 或将首帧归零；源序列的 `RateScale = 2` 必须烘焙为两倍采样率，生成序列固定 `RateScale = 1`；
3. ExitTransition 中不得有 AttackCollision、Combo/Dodge Window、Draw/Sheathe/Kinsect Commit、Cue 或资源结算 Notify；
4. 精确放置 `Action Root Motion Phase` 与 `Motion Matching Handoff`；
5. 仅为该 GA 设置允许的 Handoff 类型；
6. 建立相应 Exit PSD 与 AnimBP Exit PSD router，继续使用 `PSS_MH_Move`；router 只切换 PSD，不直接选动画；
7. 在安全尾段通过线程安全入队消费 Serial，并让 ExitTransition 再自然接 Loop、一次 Stop 或 Idle。

若没有无功能尾段，停在审计结论；不得把整个 GA Montage 加入普通 Move PSD。

## 7. 自动化与当前验收

`MHGZ.M4.4.Handoff` 的三项自动化已通过：

1. `RootMotionPhaseIsExact`：错误 Token 无法结束别人 Phase；Phase 未结束的 Handoff 失败并保持 owner；安全 Handoff 才释放 owner；
2. `PublishesAndConsumesExactPayload`：移动尾段的真实“推杆 → 松杆”发布一次 `PendingStopAtHandoff`，源 GA 正常结束，只有正确 Serial 能消费；
3. `RejectsUnsafeOrUndeclaredRoutes`：未声明类型不结束 Action、不发布 payload。

本次验证证据（2026-08-31）：Development Editor 编译成功；`MHGZ.M4.4.Handoff` 3/3、`MHGZ.PMM.Query` 4/4 通过；`MHGZE4AnimBlueprintAudit` 已确认两个回调均含 ActionIdle 路由、`bMMExitWantsMoveDatabase` 尾段分支及最终 Idle 路由。

## 9. 2026-09-01：搜索前路由实现状态

**当前阶段：M4.4 代码实现、E4.2 自动绑定与静态验证已完成；尚处于 M4.5 PIE 固定矩阵验收，不能宣告通过。**

本轮定位到此前 E4.2 图路由的根因：`On Motion Matching State Updated` 由引擎在节点完成本帧 Pose Search 后才调用。若在该回调中调用 `Set Database(s) To Search`，候选库的改变只能影响下一帧搜索；动作 Montage 正在结束时，上一帧的普通 Move PSD 已经有机会选中 Walk/Loop/Stop，从而形成错误的 Walk、错误 Stop 或 MoveExit 暂停。

现已将职责拆开，且每个 Motion Matching 节点仍然只绑定一条对应函数：

| 回调时机 | 收刀节点 | 持刀节点 | 唯一职责 |
|---|---|---|---|
| 搜索前 `Update Function` | `OnSheathedMotionMatchingPreUpdate` | `OnUnsheathedMotionMatchingPreUpdate` | 根据 Handoff/ActionIdle 路由设置本帧候选数据库。 |
| 搜索后 `On Motion Matching State Updated` | `OnSheathedMotionMatchingStateUpdated` | `OnUnsheathedMotionMatchingStateUpdated` | 读取实际被选中的数据库和时间；仅确认 Exit 已入场、排队消费 Serial、写 Telemetry。绝不在这里改候选库。 |

原蓝图 `OnShthMmUpdate` / `OnUnShMmUpdate` 保留为历史图和调试参照，但不再负责候选数据库路由，也不得重新绑定到节点。

搜索前的原生路由状态为：

```text
Move
  -> 新的兼容 Handoff -> AwaitExitEntry -> ExitOnly / ExitAndMove
  -> 无 Handoff 的 Action 结束且无输入 -> ActionIdle

AwaitExitEntry: 仅 Exit PSD，强制重新搜索；直到搜索后确认实际选中该 Exit PSD。
ExitOnly: 仅 Exit PSD；尾帧后进入对应 ActionIdle。
ExitAndMove: 安全尾段前仅 Exit PSD；安全尾段开放 [Exit PSD, Base Move PSD]，
             真正选到 Base Move 后才回 Move。
ActionIdle: 仅 Idle PSD；第一次真实摇杆输入立即回 Base Move PSD，无时间保持。
```

这项实现明确不使用 `bMMForceIdle`、动作后 Idle 时间保持、输入死区或 PSS 权重改动作为动作退出修复。`mhgz.MM.PostActionIdleHold` 默认值为 `0`，仅保留为旧方案对照诊断开关。

## 10. 2026-09-01 PIE 回归：Exit 入场与 Notify 排序修复

最新记录 `Saved/RuntimeTelemetry/20260901-163526-BP_IG_Character_C_0-53864` 已排除“动作结束普通 Move PSD 抢选”的旧问题，但发现两个独立的 E4.2 资产合同问题：

1. 两条翻滚的 `MotionMatchingHandoff` 都被拒绝，日志为 `ActionRootMotionPhase is still active`。原先 Phase 仅在 Handoff 前一个 60fps 帧结束；UE 可以在同一次动画更新中先派发普通 Notify、后派发 NotifyState End，因此 Handoff 先看到仍活跃的 Phase。
2. 移动收刀 Handoff 成功后，孤立 Exit PSD 的首次搜索直接选中 `AS_Shth_Sheathe_MoveExit@0.3500s`。这是该 PSD 索引完整序列后 Pose Search 的合法“最佳姿势”，但不符合“指定 Exit 必须从开头交接”的合同；随后安全尾段立即开放 Base Move，表现为 Exit 没有完整播放、回 Idle 后重播 Start。

### 10.1 已实施的修复

- 三条 Handoff 的**原始 Handoff 帧不变**：收刀 115、收刀前翻滚 85、持刀前翻滚 100（均按 60fps Montage 帧）。
- `ActionRootMotionPhase` 在 Handoff 前 **3 个** 60fps 帧结束，形成 0.05s 的 Notify 排序安全间隔。这个间隔仍由原 Montage Root Motion owner 持有，不会提前把根位移交给普通 Move PSD。
- Handoff 在自己的精确帧再次读取真实摇杆；若可移动阶段曾有输入、当前已无输入，即使松杆发生在上述安全间隔内，也会发布 `PendingStopAtHandoff`。
- 三个 `PSD_MH_*Exit` 现在是 **Entry candidate bank**：唯一 Exit Sequence 的首次可搜索范围为 `0.0000–0.0333s`，`Disable Reselection=true`。首次选择只能从开头 0–2 帧进入；选中后由 UE Continuing Pose 正常播放该 Sequence 的完整时长。它们不是开放式“从任意 Exit 帧跳入”的普通移动库。

### 10.2 本轮新增 PIE 判据

记录中每个成功的移动 Handoff 必须同时满足：

1. 不存在 `[MotionMatchingHandoff] Rejected ... ActionRootMotionPhase is still active`。
2. `Selection.csv` 首个相应 Exit PSD 结果的 `SelectedTime` 必须在 `[0.0000, 0.0334]`，不能是 Exit 尾帧。
3. 全程推杆：Exit Sequence 先连续播过，再由真实 Base Move 候选接管；不得先 Idle、暂停或重播 Start。
4. MoveExit 中松杆：Exit 仍连续播完；随后仅由现有 M4.2 一次 Stop 生命周期处理，不得长距离滑行、突然强制 Idle 或重复 Stop。
