# E4.2 动作退出 Exit PSD 路由与验收

> **状态（2026-09-01）：E4.2 与 M4.5 PIE 固定矩阵已签收。** 本文保留为已完成的 Exit 路由合同与回归清单；当前阶段已进入 M4.6。不得把完整 Montage 加入普通移动 PSD。

## 1. 范围与已完成资产

本轮只为已审计的移动退出提供 ExitTransition；不为没有安全无功能尾段的动作伪造 Exit Sequence。

| 路径 | Handoff 类型 | Exit PSD | Exit Sequence | 有效时长 |
|---|---|---|---|---:|
| 移动收刀 `AM_IG_ShouDao` | `SheatheMoveExit` | `PSD_MH_Shth_SheatheExit` | `AS_Shth_Sheathe_MoveExit` | 0.3500 s |
| 收刀前翻滚 `AM_Shth_Dodge` | `DodgeMoveExit` | `PSD_MH_Shth_DodgeExit` | `AS_Shth_Dodge_MoveExit` | 0.2667 s |
| 持刀前翻滚 `AM_IG_Dodge_Forward` | `DodgeMoveExit` | `PSD_MH_UnSh_DodgeExit` | `AS_UnSh_Dodge_Forward_MoveExit` | 0.5667 s |

三个 PSD 都使用 `PSS_MH_Move`，各自只含一条 Exit Sequence，`Disable Reselection = true`、`Continuing Pose Cost Bias = -0.05`。生成序列已按实际采样率烘焙，`RateScale = 1.0`；不得把它重新改为 `2`，也不得重基 Root Track。

`AM_IG_TuCi` 和拔刀攻击仍没有审计通过的无功能 ExitTransition，因此**没有** `AttackExit` / `DrawExit` 的资产 Handoff。它们结束后无输入时由下文的 ActionIdle 候选语境回 Idle；这不等于把它们纳入 Exit PSD，也不等于允许它们使用本轮的 Exit Sequence。

## 2. 当前已保存的 AnimBP 路由

`ABP_MH_Character` 的两个 Motion Matching 节点已由 `MHGZE4PreSearchRouting` 自动绑定到原生回调：搜索前分别为 `OnSheathedMotionMatchingPreUpdate` / `OnUnsheathedMotionMatchingPreUpdate`，搜索后分别为 `OnSheathedMotionMatchingStateUpdated` / `OnUnsheathedMotionMatchingStateUpdated`。所有候选库选择均在 C++ 搜索前回调执行；不要手工恢复旧的 `OnShthMmUpdate` / `OnUnShMmUpdate` 图，也不要绑定第二个同阶段回调。

路由合同如下：

```text
功能 Montage 结束
├─ 已收到移动 Handoff
│  └─ 先只搜索对应 Exit PSD
│     ├─ 持续推杆
│     │  └─ Exit 持续播放；仅在尾段开放 [Exit PSD, 普通 Move PSD]
│     │     └─ 正常进入 Loop / Cruise，保留原移动边缘，不重播 Start
│     ├─ 移动阶段曾推杆后松杆（`StopRequestActive = true`）
│     │  └─ 当前 Exit 立即让出 continuing pose，仅搜索普通 Move PSD
│     │     └─ M4.2 的一次正常 Stop 直接开始；不等待 Exit 尾段，不形成输入死区
│     └─ bMMExitWantsMoveDatabase = false
│        └─ 不开放普通 Move PSD；Exit 到末帧后切入对应 ActionIdle PSD
└─ 没有移动 Handoff，且动作结束时没有移动输入
   └─ C++ 发布一次 ActionIdle context
      └─ 只搜索对应 ActionIdle PSD，直到有新的移动输入
```

ActionIdle 资产是：

- 收刀：`PSD_MH_Shth_ActionIdle`；
- 持刀：`PSD_MH_UnSh_ActionIdle`。

它们各自只有该姿态的循环 Idle。这使“无输入却因脚部姿势成本选中 Walk/Run Loop”在候选集层面不再可能，而不是依靠降低 `MM_Intent`、长 Blend、强制 Idle 时间或输入死区掩盖。

当 `bMMHasLocomotionInput` 首次变为真时，回调以 `InterruptOnDatabaseChangeAndInvalidateContinuingPose` 恢复节点原有的普通 Move PSD，并清除 `MM*ActionIdleActive`。因此这不是输入锁：新的移动输入立即被正常移动系统接收。

## 3. 路由状态与调试接口

两个回调中已有如下成员状态（均由自动工具维护）：

| 组 | 收刀节点 | 持刀节点 | 作用 |
|---|---|---|---|
| Exit 路由 | `MMSheathedActionExitRoute`、`MMSheathedActionExitSerial`、`MMSheathedActionExitSelectedTime` | `MMUnsheathedActionExitRoute`、`MMUnsheathedActionExitSerial`、`MMUnsheathedActionExitSelectedTime` | C++ 记录当前 Exit 的候选集、来源 Handoff 和已连续播放到的时间。 |
| ActionIdle 状态 | `bMMActionIdleContextActive`、`bMMActionIdleContextUnsheathed` | 同左 | 保持 Idle-only 候选集，直到出现真实新输入。 |
| Stop / Exit 输入 | `bMMStopRequestActive`、`bMMExitWantsMoveDatabase` | 同左 | 实际松杆时，立即让非功能 Exit 交给普通 Move PSD 的一次 Stop；持续输入时才开放 Exit 尾段。 |

`bMMExitWantsMoveDatabase` 只在两种情况下为真：交接时仍有实际移动输入，或可移动阶段确实出现过“推杆后松杆”而需要把**一次**合法 Stop 交给 M4.2。没有输入的退出绝不因此打开完整 Move PSD。

`MMActionIdleContextSerial` 的消费仅从 AnimBP 回调入队；下一次 `NativeUpdateAnimation` 才清除 C++ context。不要在蓝图线程中访问 RuntimeHost 或直接清 pending payload。

## 5. M4.5 PIE 固定矩阵（已通过，保留作回归）

启动新编辑器后，以真实角色实例作为 `ABP_MH_Character` 的 Debug Filter；如需证据，录制 Runtime Telemetry。逐项测试：

1. **拔刀 / 突刺，未推摇杆：** Montage 结束后只能留在对应 Idle；不得出现一小段 Walk/Run Loop、Stop 或自动位移。
2. **静止收刀，未推摇杆：** 收刀后保持收刀 Idle；不得无限 Walk/Loop。
3. **移动收刀，始终推杆：** `SheatheMoveExit` 自然交给普通移动；不暂停、不重播 Start。
4. **移动收刀，中途松杆：** 下一次 MM 搜索即从 Exit 交给 M4.2 的一次合脚 Stop；不得等待 Exit 播完、长距离滑行或突然强制 Idle。
5. **两种前向翻滚（收刀、持刀）：** 分别重复第 3、4 项和“全程不推杆”项；持刀翻滚不得错误选收刀 Exit。
6. **连续动作回归：** 拔刀、Y 突刺、收刀、翻滚交替触发；上一动作的 Handoff / ActionIdle serial 不得影响下一动作。

Telemetry 中核对：移动 Handoff 有新 serial 后被消费；无 Handoff 的动作结束时仅短暂出现 ActionIdle context；全程未推杆的 Exit 结束前 `bMMExitWantsMoveDatabase = 0`，且没有普通 Move PSD 的 Loop/Stop 结果。

## 7. 2026-09-01 自动绑定更新：不要再编辑旧回调图

本节替代本文此前关于 `OnShthMmUpdate` / `OnUnShMmUpdate` 的手工候选库连线说明。

`ABP_MH_Character` 的两个 Motion Matching 节点现由
`MHGZE4PreSearchRouting` Commandlet 自动保存为以下绑定：

| 节点 | 搜索前 Update Function | 搜索后 State Updated Function |
|---|---|---|
| 收刀 Move PSD 节点 | `OnSheathedMotionMatchingPreUpdate` | `OnSheathedMotionMatchingStateUpdated` |
| 持刀 Move PSD 节点 | `OnUnsheathedMotionMatchingPreUpdate` | `OnUnsheathedMotionMatchingStateUpdated` |

只允许每个属性绑定一条函数；这不是限制，因为两种职责已经分别使用两个引擎回调时机完成。不要尝试把多个函数串联到同一个下拉框，也不要把 `Set Database To Search`、`Set Databases To Search`、`Reset Database(s) To Search` 放回 `On Motion Matching State Updated` 或旧蓝图图表。

原因是：`State Updated` 发生在本帧 Pose Search 之后，放在那里必然至少滞后一帧；`Update Function` 才是在搜索前，因此可阻止普通 Move PSD 在 Handoff 帧抢先选 Walk/Loop/Stop。

本轮已经无需额外的可视化编辑器接线。打开编辑器后只需进行第 5 节 PIE 验收；若需确认绑定，选中节点后应能在 Details 中看到上述两个原生函数名。
## 8. 2026-09-01：单一完整 Exit PSD、首帧入口与 3 帧排序安全间隔

三个已批准的 `PSD_MH_*Exit` 都完整索引其唯一 Exit Sequence，`Sampling Range=[0,0]`；`Disable Reselection=true` 与 `Continuing Pose Cost Bias=-0.05` 保持不变。每条 Sequence 的 `PoseSearchBlockTransition` 从 `1/60s` 延续至末帧：新搜索只能命中起始开口，同一 PSD 的 continuing pose 则能自然穿过被阻断的主体。不要改为独立 Entry PSD 或缩短为独立索引范围；跨 PSD 后的新搜索会重新跳入尾段。

`ActionRootMotionPhase` 结束帧也已由 Commandlet 自动设置为 Handoff 前 3 个 60fps Montage 帧：

| 路径 | Phase 结束 | Handoff |
|---|---:|---:|
| 移动收刀 | 1.8667s | 1.9167s（115 帧） |
| 收刀前翻滚 | 1.3667s | 1.4167s（85 帧） |
| 持刀前翻滚 | 1.6167s | 1.6667s（100 帧） |

Handoff 的帧位没有移动。不要手工缩短这一间隔；它避免 UE 在同次动画更新中先触发 Handoff、后结束 NotifyState，导致 Handoff 被安全拒绝。

PIE 中的资产判据：查看 `Selection.csv`，每次成功移动 Handoff 首个 Exit PSD 的 `SelectedTime` 必须不大于 `0.0334`。若出现 `0.2667`、`0.3500` 等尾段时间，说明起始 BlockTransition 被错误重建，必须先回到本节检查，不要调 PSS 权重。中途松杆时，下一帧应切到普通 Move PSD 的 Stop；持续推杆时才允许 Exit continuing pose 走向尾段。
