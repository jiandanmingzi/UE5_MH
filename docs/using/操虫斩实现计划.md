## 1. 目标与已定约束

做空中 `B` 和 `RT+B` 的**同一个**操虫斩 GA：`186` 悬停定向 → `187` 三维前冲 → 未命中 `188` 下落/落地，或有效命中 `189` 舞踏。它须在空中回避可行动点后真正接管旧动作。强化操虫穿刺、觉虫击等后继招式不在本轮，但 `189` 必须留下正确舞踏来源与可行动点。

1. `B`、`RT+B` **共用同一个 `KinsectSlashDashProfile` 和 `.25s` 前冲时长**，仅方向来源不同。默认走 §3.2/§9.4 的分段解析位移；水平无接触时位移约 `(839.5125,0,-22.5625)cm`。同距离要求指共享同一组运动参数，不要求上下冲的水平投影距离一致。旧 `KinsectSlashMaxDistance=840`、归一化距离曲线和 `.242s` 仅在显式关闭 `bUseCapturedKinsectSlashDash` 后作为兼容路径使用，不再是默认合同。
2. `B` 在锁定点取角色水平 Forward；`RT+B` 在锁定点取准心对应的三维方向（可上、下、左、右），不是按键时的旧 AimSnapshot。锁定后不再追踪相机/目标。角色胶囊保持直立，仅 Actor Yaw 可转。
3. 默认前冲由一个 ActionToken 拥有的 CMC 分段运动租约驱动；表现动画不再推动胶囊。取消、死亡、换武器、接管、蒙太奇失败都要释放该租约及旧阶段 RMS、攻击窗、Tag，旧任务不得清理新任务的所有权。
4. 准心射线只选方向；只有 **`Attack Collision[0]` 的猎虫伤害**真实命中怪物 Hitzone 且 Damage GE **成功提交**才尝试点灯、请求 `189`；确认舞踏起播后才加舞踏层并重置预算。武器段 `[1]`、`[2]` 的成功伤害不点灯、不单独触发舞踏；墙体/胶囊接触不算攻击命中。
5. 未命中 `187→188` 继承末速度，再由 CMC Falling 和 Host 落地收尾；不以静止/强制 Idle 掩盖速度断层。
6. 普通动作继续遵守输入快照不可变。**只有本招 186 的定向事件**允许一次带 Token 校验的实时相机采样；需更新注释和测试，不把其他 GA 改成每帧重读。
7. 猎虫在 186 起手与 187 前冲期间保持棍尾前方的局部附着位置，不能使用“胶囊位置 + 发射方向偏移”冒充。附着时长与伤害窗时长独立。命中、未命中、取消/落地都必须解除本 Action 的临时占用并回到正常手臂回收流程。
8. Actor/胶囊保持直立，锁定的三维方向另驱动最终骨架姿势的整身俯仰。武器和附着猎虫跟随实际Socket，攻击Sweep读取修正后的世界位置；不旋转胶囊、不改Mesh组件导入朝向，姿态修正本身不改位移算法。相机上限56.25°；187正向RT+B当前暂以观察上限53.74°钳位，二者不假设相等。53.74°是捕获样本的观察最大值，不是已证实的原版硬限角。

## 3. 方向、位移与命中：实现合同

### 3.1 输入路由和定向点

### 3.2 187：捕获分段方向运动（当前生产默认）

当前生产默认不再消费 `840*C(u)`、`.242s` 的旧标量曲线。`UInsectGlaiveCombatConfig` 使用 `bUseCapturedKinsectSlashDash=true` 与 `FSegmentedDirectionalMovementProfile KinsectSlashDashProfile`；`EWeaponMovementMode::SegmentedDirectional` 是追加到既有枚举末尾的新模式。`B` 与 `RT+B` 按用户的同距离要求共用这一份 profile，不能据此声称它重现了原版每次 B 或每次接触。

令 `D` 为锁存的归一化三维 `LaunchDirection`，令 `F = Normalize2D(D)` 为世界水平投影；悬停阶段位移为零。CMC 以游戏秒分三段并负责 Sweep：

- hold：`.0083333333s`（`1/120`）；
- straight：`.0833333333s`（`5/60`），`v = 6600D`，位移为 `D*550cm`；
- glide：`.1583333333s`（`9.5/60`），总时长 `.2500000000s`，`u` 从 glide 起点计，`u∈[0,.1583333333]`。

glide 的解析式为：

```text
a = 360F + (0, 0, -1800)
p(u) = D*550 + 1800D*u + .5*a*u^2
v(u) = 1800D + a*u
```

当 `D` 水平时，终点为 `p=(839.5125, 0, -22.5625)cm`、`v=(1857, 0, -285)cm/s`。这组公式替代旧 `840*C(u)` 和旧 `.242` sample-span **仅作为当前默认位移实现**；`KinsectSlashDistanceCurve`、`KinsectSlashDashDuration`、`KinsectSlashMaxDistance` 等旧序列化字段仍保留，只有显式 opt-out（`bUseCapturedKinsectSlashDash=false`）才走兼容路径。既有 CurveAsset、Montage 窗口、Socket 与 Input 不重建；Combo 仅按 §9.5 迁移两条保存行的废弃门控依赖。

CMC 在 phase boundary 拆分 Sweep，并把同一 Movement Update 的剩余 `dt` 交给 `188 MOVE_Falling`；任务读取 `188` 部分更新之后的**当前 CMC velocity**，不把速度回读/回写到 boundary，也不 rewind。碰撞不提前终止 dash：法线投影与 side-slide 继续，只有实际 Landing 结束空中物理。自然结束、同帧源替换和取消分别遵守 §9.4 的速度与所有权合同。

原版行为边界仍须保留：非瞄准样本出现过不同系数（straight 约 `6000`、glide 重力约 `0`、水平加速度约 `720`、竖直约 `-180`），而输入列有 `nil`，不能据此可靠标注按钮。最新零 LS aim-glide 样本说明仅沿水平投影 `s` 不是三维残差；不要宣称当前共享 profile 是原版 B 或每次接触的精确重建。`53.74°` 是 Rise 捕获到的最高上冲观测，不是已证明的硬上限；当前正向 RT+B cap 仍是 provisional tuning，CameraManager 上限保持 `56.25°`。

### 10.2 必须保持的合同与禁止修改项

1. B/RT+B仍指向同一个GA；普通B附加俯仰为0，RT+B的俯仰来自同一次AimLock保存的LaunchDirection。两路继续共用MaxDistance、C(u)和DashDuration。
2. Actor/Capsule Pitch与Roll保持0，Actor Yaw仍按方向XY投影处理。摄像机上下观察不直接驱动胶囊倾斜。
3. 整身俯仰只修改最终骨架姿势，不修改Mesh组件的RelativeRotation/RelativeLocation、导入资产轴向、Socket局部Transform、动画源位移或CMC/RootMotionSource轨迹。不得通过给动画再次开启根位移补姿态。
4. 准心锁向只发生一次，保留约0.317游戏秒AimLock和现有DashBegin等通知。锁点后转镜头/松RT不能重新锁方向；姿态插值也不能成为重新采样相机的理由。
5. 既有三伤ConfigIndex、GE、Socket名字、通知轨道/准确窗口、命中去重、猎虫回收和189来源不变。姿态改变只让原判定随实际武器位置改变，不新建上下方向GA/GE，不复活独立Probe。

### 10.3 镜头限角：统一PlayerCameraManager配置

**方案**：新增轻量`AMHGZPlayerCameraManager : APlayerCameraManager`，构造默认`ViewPitchMin=-66.09f`、`ViewPitchMax=56.25f`；在`AMHGZPlayerController`构造中指定该类。该边界只约束镜头。原作录制的187上仰发射最大角约`53.74°`，故`DA_IG_Combat`另提供`KinsectSlashMaxUpwardLaunchPitchDegrees`（默认53.74°），由本招GA仅在RT+B锁向后限制正向发射俯仰。镜头可继续上抬到56.25°；不能把两者误作同一个角度限制。

实施与接线要求：

- 新源码位置为`Source/MHGZ/MHGZPlayerCameraManager.h/.cpp`，对应修改`Source/MHGZ/MHGZPlayerController.cpp`。不改已有镜头距离、高度、FOV、SpringArm跟随及镜头碰撞。
- 回读`/Game/Blueprints/PlayerController/Demo/BP_MHGZ_PlayerController`的Class Defaults → Player Camera Manager Class。若序列化为None或旧覆盖值，增量配置为新原生类；不要求为了两项参数额外建立一个蓝图。若之后需要蓝图调参，再创建该原生类的派生蓝图并显式赋给Controller。
- 鼠标和右摇杆继续走已有Look → AddControllerPitchInput；统一通过CameraManager的正常视角处理钳制。不要分别截断两个输入轴，不要每Tick临时改限角，也不要只在操虫斩期间限角。
- 验证实际生成的CameraManager类及最终PlayerViewPoint Pitch，而不只检查蓝图默认值。角度读取需要归一化到−180°～+180°，不能把表示同一角度的293.91°误判为超过上限。
- `CaptureAimLockSample()`沿用当前第三人称视差与LimitViewPitch。目标很近时，猎人到目标的角度可能比相机射线更陡；锁向后RT+B GA再施加独立的上仰发射角上限。钳制后不保证直线穿过原ImpactPoint，这是射程/角度约束的结果，不通过假命中补偿。

原录制的相机俯仰范围为−66.09°～+56.25°，突进发射俯仰范围为−71.07°～+53.74°，两者不等角。当前实施只从数据采用正向发射上限53.74°，不把统计拟合`0.921×相机角+0.34`硬写进代码；下俯角保持原有相机/视差锁向，不在本次新增钳制。

### 10.4 方向数据流：位移、姿态、判定共用锁向

```text
鼠标/右摇杆 → Controller视角 → CameraManager限角 → 当帧PlayerViewPoint
  → 186 AimLock：屏幕中心射线 + 第三人称视差 → RT+B正向发射俯仰上限53.74°
  → 唯一Locked LaunchDirection
     ├─ XY投影 → Actor Yaw（胶囊始终直立）
     ├─ 完整XYZ → 187 CurvedDirectional位移（保留现有C(u)）
     └─ 俯仰/姿态旋转差 → 最终骨架姿势 → 手部/武器/IG_Kinsect世界位置
                                              → 原三段Socket Sweep → GE/精华/舞踏
```

普通B在同一锁点使用角色水平Forward，绕过准心方向采样，额外姿态旋转为单位旋转。RT+B从**最后保存的LaunchDirection**计算姿态，不在AnimBP重新读相机、不从当前速度推俯仰；速度可能受墙体/下坠影响，不能反向改变已锁攻击姿态。

新增诊断保留锁点CameraOrigin/Direction、TargetPoint、LaunchDirection、AimSource、bUsedActorForwardFallback。若发射向量无效，继续使用当前有日志的水平回退，姿态也回退为单位旋转，不能出现位移用水平而姿态用旧角度的混搭。

### 10.5 整身俯仰数学与项目特殊骨架轴

对归一化锁向`D`，令`H=Normalize(D.X,D.Y,0)`。附加俯仰角为：

```text
PitchDegrees = Degrees(atan2(D.Z, sqrt(D.X² + D.Y²)))
QWorld       = 从水平H旋转到D的最短弧四元数
QComponent   = inverse(QMeshWorld) × QWorld × QMeshWorld
QApplied     = Slerp(Identity, QComponent, VisualPitchWeight)
```

`QMeshWorld`来自实际Mesh组件世界旋转，已包含Actor Yaw和导入适配旋转。`QComponent`是**组件空间旋转差**，不是目标骨骼的绝对朝向。已有动画骨骼旋转必须保留，只叠加该差值；骨架根的动画平移保留，不附加世界位移。角度范围排除了垂直/反向奇点，但仍要拒绝NaN/非有限输入、处理零XY投影并走显式安全回退。

项目已知导入轴向是骨架局部+Z朝预览世界+Y、局部+Y朝预览世界−Z、X不变。因此禁止把`PitchDegrees`直接当“骨骼本地Pitch”填入，也禁止为此重导入/旋转源动画。上述空间转换的目标是：无论导入基准如何，修正始终让世界水平前向抬到/压到D，而不是向上爬或侧翻。

**落点**：`ABP_MH_Character`最终蒙太奇Slot输出之后、Output Pose之前。对真实角色骨架的根骨骼作组件空间附加旋转，使其全部子骨骼一起倾斜。根骨骼名在实施前从Skeleton Tree/索引0回读，不能假定与武器判定用的`Root`是同一根骨骼。首版绕骨架根的现有位置旋转；若极端角下中心明显错位，先记录根位置/胶囊/模型差值定位，不借修改胶囊、Mesh组件位移或碰撞半径掩盖。

### 10.7 状态所有权、原生接口与AnimInstance变量

以下名字是**待新增接口合同**，不是现有可用节点。实现时如按项目命名规范微调，必须同时回填本节。

**唯一写者**：本次`UMHGZKinsectSlashAbility`；**状态保管与有效性**：现有`UMHGZWeaponRuntimeHostComponent`；**只读表现消费者**：`UMHGZMotionMatchingAnimInstance`及其派生`ABP_MH_Character`。不新建独立Tick组件来同时改Mesh/朝向，不通过遍历全部激活GA让AnimBP猜谁是操虫斩。

在`MHGZWeaponRuntimeTypes.h`新增小型`FWeaponActionVisualPitchState`，至少包含：

| 字段 | 类型/单位 | 用途 |
|---|---|---|
| OwnerAction | FWeaponActionToken | 精确到本次激活及Runtime Generation，不只比较AbilityClass。 |
| SourceMontageInstanceID | int32 | 限定当前186/187/188实例；189交接先退出旧前冲状态，不让旧实例继续写。 |
| LockedDirection | FVector，单位向量 | 同一次AimLock最终方向，不缓存第二套相机角。 |
| TargetWeight | float，0～1 | 相位控制的目标权重；GA只改变目标，不每帧改骨骼。 |
| BlendInSeconds / BlendOutSeconds | float，游戏秒 | 可调混入/退出时间；有限且非负。 |
| StateRevision | uint32或项目既有单调序列类型 | 区分同一Action相位更新，防止旧缓存/回调覆盖较新状态。 |

Host拟提供`TrySetActionVisualPitchState(State)`、`ReleaseActionVisualPitch(ActionToken, ReleaseMode)`及游戏线程只读快照接口。新增`EActionVisualPitchReleaseMode`明确区分`BlendOut`正常视觉退出与`ImmediateReset`异常硬清理，不能由AnimBP根据“快照消失”猜测释放原因。Set验证当前Runtime/已注册Action、Montage归属、有限方向/时长；Release只释放精确匹配所有者，幂等，旧Action释放不能清新Action。Shutdown、UnPossessed、武器重建与Mesh/AnimInstance重初始化要清理状态及回调；并发替换不得先广播旧清理再无条件抹掉新状态。

平滑退出必须与“仍有写权”分开：若正常退出后需要保留0.1s淡出，只留下不可改目标的退休快照，由AnimInstance完成单位旋转恢复；退休数据不提供碰撞/资源/输入权限，新Action取得姿态槽时丢弃旧退休快照。异常硬清理不得等待Timer。当前Active快照与退休快照都不能持有失效Ability对象强引用延长GA生命期。

AnimInstance在游戏线程读取Host快照并缓存；并行动画评估只消费自己的数据，不从线程安全图函数中调用Controller、Host或GA可变对象。实现时明确使用该版本允许访问游戏对象的更新入口/Proxy预更新，不因为函数叫NativeUpdateAnimation就省略线程检查。

新增只读变量（不要求用户手建同名蓝图变量）：

| AnimBP显示名 / C++建议名 | 类型 | 默认值及意义 |
|---|---|---|
| Action Visual Pitch Active / bActionVisualPitchActive | Boolean | false；当前有效状态或正常退休淡出是否需要修正。 |
| Action Visual Pitch Degrees / ActionVisualPitchDegrees | Float，度 | 0；锁向的诊断角度，不直接当骨骼本地Pitch使用。 |
| Action Visual Pitch Weight / ActionVisualPitchWeight | Float | 0；平滑后的0～1权重。 |
| Action Visual Pitch Component Rotation / ActionVisualPitchComponentRotation | Rotator | 0；由正确空间转换和权重插值得到的组件空间旋转差，供Modify Bone使用。 |

旋转插值以四元数做，最后才转为Rotator供蓝图节点读取，避免Euler回绕。权重按实际游戏DeltaSeconds演进，在30/60/120FPS及slomo下保持游戏时间一致；方向不插值重采样。BlendIn/Out建议放在`UMHGZKinsectSlashAbility`的独立`Visual Pitch`配置栏，默认0.1s；角度上下限只在CameraManager，不再复制到GA。

### 10.8 AnimGraph接线、Socket传播与同帧采样门禁

**目标接线**（保留原MM、LocomotionBase、上身分层、Pose History和各Slot）：

```text
现有最终Slot（通常为DefaultSlot）
  → Local To Component
  → Transform (Modify) Bone：实际角色根骨骼
      Translation Mode = Ignore
      Rotation Mode    = Add to Existing
      Rotation Space   = Component Space
      Rotation         = Action Visual Pitch Component Rotation
      Scale Mode       = Ignore
      Alpha            = 1（旋转输入已含平滑权重）
  → Component To Local
  → Output Pose
```

不要又给节点Alpha接ActionVisualPitchWeight，否则会对已加权旋转二次衰减。无有效状态时Rotation为0、整个节点等效不改变姿势。此层必须位于最后一个可能覆盖全身的Slot之后；放在DefaultSlot前会被操虫斩Montage覆盖，放在Pose History前会污染普通MM查询。若当前图最终节点不是DefaultSlot，以实际图为准，只增量插入这一层。

**Socket传播**：角色最终姿势 → 手部附着点 → 武器组件Transform → 武器`IG_Kinsect/IG_RearTip/Root/IG_FrontTip` → 猎虫临时附着位置和Sweep。保持已有附件关系，不手工给判定球再旋转一次，不让虫体一份偏移而段0又用另一份偏移。

**时序不是默认已通过**：当前Notify Begin/Tick直接调用基类Sweep。已读UE5.6源码：正常求值路径的`FinalizeBoneTransform()`先完成父类骨骼最终化，再派发队列Notify，最后广播骨骼最终化委托；`NativePostEvaluateAnimation`发生在后续缓冲翻转/最终化之前。因此**不能断言现有Notify一定读上一帧，也不能把PostEvaluate当成Socket终态屏障**。不可见的Montage-only Tick、URO跳过求值、BranchingPoint及独立武器TraceMesh仍有不同路径，需记录“姿态最终化→武器附件变换可用→本窗Socket采样”的真实顺序。角色最终化不自动证明武器自身骨骼与附件已更新。

1. 先以动画评估序号/帧号记录角色骨骼最终化、武器Transform、Notify Begin/Tick/End和采样位置，确认现有路径能否保证同次最终姿势。核对资产Notify的Queued/BranchingPoint模式及角色/武器的URO、可见性/骨骼刷新策略；战斗判定需要的骨骼必须实际求值，收到Notify或最终化委托不等于本帧产生了新姿势。若能证明原Notify采样已正确，沿用原路径，不无故重写其他GA。
2. 若证实采到旧姿势，保留Notify作为伤害窗时间来源，为本招增加**受Token约束的同次姿态最终化采样交接**：Begin/Tick登记待采样请求，到角色骨骼与武器附件Transform均可读取的安全点再消费；不以NextTick Timer等价替代，不为判定主动再推进一次动画。
3. 请求携带RuntimeToken、ActionToken、MontageInstanceID、ConfigIndex、窗口代次及该次评估序号。消费前重新检查所有权/取消状态，去重为每窗每次评估最多一份有效采样；只对本招启用，其他GA默认行为不变。
4. 若End与待采样请求同帧发生，正常到期不得先销毁窗口而丢掉边界前合法的最后样本；需要窗口关闭事务/合法时间区间。UE队列派发中旧窗End可先于活动窗Tick，Montage结束也可早于最终化委托，不能只在该委托中遍历“还存在的窗口”。取消、接管、换武器等异常关闭则立即作废旧请求。结束边界之后不能补伤害，188源帧14起不得因排队迟到而重新获准命中；跨完整短窗时没有合法姿势样本不能用窗外位置猜一次命中。
5. 每次采样的两个端点都来自修正后的Socket，并与真实显示模型同源。窗口首次采样不能从上次动作残留位置扫过来；正常同窗187→188则保留连续历史。姿态从水平混入的历史只在真实伤害窗内参与Sweep，不能将窗前0.1s整段混入路径当攻击。
6. 不在动画工作线程提交GAS/切Montage；安全点可能触发伤害回调/取消重入，仍遵守现有GE成功、下一帧舞踏交接和Token重新验证合同。所有姿态/附件操作均不能增加一份RMS或更改抽取的Root Motion；不能在Notify内部递归强刷一次动画/骨骼兜底，UE有PostAnimEvaluation重入检查。

本段允许两条实现结果（已证明原顺序正确则保留；发现旧姿势才改采样交接），**并不允许跳过顺序验证**。若API无法提供同次安全采样，先冻结最小修订设计与测试，再实现；不得静默接受一帧错位或扩大球半径掩盖。

### 10.10 遥测与自动化验收

复用现有`Saved/RuntimeTelemetry/<会话>/`分类与`mhgz.Telemetry.*`指令，不重新命名全系统。扩展分类README/字段说明，并在**动作事件点**记录AimLock、姿态请求/释放、最终化/碰撞窗口，不能仅依赖60Hz周期采样推断同帧先后。

| 分类 | 新增/核对字段 |
|---|---|
| 实际输入/解析输入 | 原始Look轴、RT/B边沿、ResolvedInputTag/AimSource；不是把“相机变化”当RT是否按住的证据。 |
| 角色状态 | ActionToken/Runtime Generation、姿态状态Owner/Revision、释放原因；原有资源/精华/舞踏层不删。 |
| 角色位置/朝向 | Actor Pitch/Yaw/Roll、胶囊与Mesh组件变换、根骨骼最终世界变换；区分Actor=0和骨架确实倾斜。 |
| 动画/动作 | 主/舞踏MontageInstanceID、Section/源时间、LockedDirection/Pitch、TargetWeight/AppliedWeight、组件空间修正旋转、角色姿态最终化序号。 |
| 瞄准 | 实际CameraManager类、ViewPitchMin/Max、PlayerViewPoint Pitch、锁点CameraRay/TargetPoint/LaunchDirection、是否回退及原因。 |
| 碰撞/附件 | ConfigIndex/窗口代次、武器Transform、IG_Kinsect/RearTip/Root/FrontTip采样点、猎虫世界位置、实际采样序号/采样点、Hitzone与GE结果。不能只记球心而不记真实虫体位置。 |
| MM | 原字段保持；核对姿态层没有改变Query、Pose History或产生动作退出强制Idle/错误Stop。 |

自动化最小矩阵：

1. **角度**：镜头上/下极限及回绕角表示正确；B任意镜头角仍水平，RT+B上下方向符号正确；视差/近目标钳制和无Controller回退不产生NaN。镜头类/蓝图覆盖实际回读。
2. **坐标**：Actor Yaw为0/90/180/−90、正/负俯仰、项目特殊Mesh基准旋转；水平H经修正得到D，Actor Pitch/Roll仍0，Mesh组件变换不变，零权重与普通动画输出等价。
3. **锁向**：锁点前改变准心影响结果，锁点后改变镜头/松RT不影响LaunchDirection或187姿态；普通B不读锁点相机。
4. **相位**：首个187伤害样本前混入完成，188补判期间姿态连续，帧14后退出，189第二窗前旧前冲修正已退出；188末帧保持、CMC Falling和§9速度/重力不变。
5. **生命周期**：过期Token/旧Montage/重复Notify、关停/换武器/落地/取消/接管、无效参数、AnimInstance重建、伤害/资源回调重入；旧释放不能清新状态，异常请求不遗留姿态。
6. **判定同步**：真实骨架/武器附件加载后比较Debug模型与实际Socket/Sweep；30/60/120FPS、并行动画开/关、同帧Begin/Tick/End和187→188切段、0/1重叠、最后合法样本及帧14截止。无三伤重复/丢失，不把旧姿态误算为当前样本。
7. **运动隔离**：有/无姿态修正对照，胶囊位置/速度与RootMotionSource同输入等价；不增加抽取根位移、不改变187/188/189/157档位。空回/撑杆跳、送虫/收虫、其他GA碰撞、普通MM启停无回归。

数学/所有权单测不能代替真实AnimGraph与附件采样测试。若某项因真实资产未接线不能自动验证，标成待E1/E2，不能直接算通过。新冷编译/专项/全量/DataValidation结果单独记录实际数量与路径，不复用§9的26/26、146/146和596作为新增成绩。
