## 验证规则

**接下来除非必要（用户指明，或者修改幅度很大等），都不再需要进行回归性测试和全量验证所有资产。**

普通小改动先核对相关代码、资产或日志，只做直接相关的最小检查。用户明确要求、跨系统/公共接口、较大资产迁移、实际回归证据或正式发布时，再按风险扩大范围；不因归档中的旧流程默认启动回归套件、PIE矩阵或全项目DataValidation。

封存保留测试、录制器、遥测、断言和按需检查能力，不删除测试或关闭运行时保护。报告区分编译、定向检查、资产保存、独立回载与用户PIE签收，不把未执行的检查写成通过。

## 日常执行

- 小修按“定位相关事实 → 修改 → 直接相关的最小检查”完成；复杂公共接口或生命周期改动再使用完整设计与独立审查。
- 先读涉及的现有代码、资产和设计，不整批重读历史文档。工具先查[Scripts README](../../Scripts/README.md)和[工具索引](../../Scripts/tool-index.md)，复用已验证的UE桥接及`ue_asset_utils.py`，不重复造工具。
- 编辑器打开时用`Scripts/ue_remote.py`；关闭时使用既有Commandlet。纯资产修改不编译C++；代码修改集中后增量编译。
- 远程超时可能已发生写入，先核对保存后状态；同一失败没有新证据时不重复执行。保留用户未提交改动、原通知GUID/窗口/轨道和未改范围，写入前按需备份。
- 用户已有授权和签收持续有效。继续任务从未完成项接续，不因历史“待验证”重复要求录制、申请权限或执行已完成的Apply。
