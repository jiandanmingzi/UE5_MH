## 验证规则

**接下来除非必要（用户指明，或者修改幅度很大等），都不再需要进行回归性测试和全量验证所有资产。**

普通小改动先核对相关代码、资产或日志，完成与改动直接相关的最小检查即可；不因历史流程或文档中的旧门禁，默认启动回归套件、PIE矩阵或全项目 Content DataValidation。只读检查也应聚焦当前问题。

以下情况再启用更广的验证：用户明确要求；改动跨越多个系统或公共接口；影响大量序列化资产、生命周期或资源所有权；出现证据表明有回归风险；或进行正式发布。即使启用，也先按风险选择相关测试和资产范围，只有确有必要才扩大到全量。记录实际执行的命令与结果，不把未执行的检查写成通过。

封存只改变日常执行规则：测试源码、测试筛选名、M阶段分类、录制器、遥测和定向诊断工具继续保留且可按需使用；不删除测试、不更改断言、不关闭运行时检查或 Unreal 正常资产检查。

## 日常执行

普通小修使用“定位相关事实 → 修改 → 直接相关的最小检查”。已明确的任务无需重新建立完整阶段计划。复杂公共接口、生命周期或大规模资产变更再采用完整设计和审查。

工具入口见 [Scripts README](../../Scripts/README.md)，所有脚本的发现索引见 [tool-index](../../Scripts/tool-index.md)。新脚本应说明已有工具缺少的能力；可参数化的已有工具优先扩展。读取 UE 数组、映射、ScalableFloat 和蓝图默认对象时复用 `Scripts/ue_asset_utils.py`。

连接或执行失败先定位到“发现编辑器、建立连接、接口能力、脚本执行、保存、引用、运行时”中的一层。同一输入重复失败且没有新证据时更换诊断步骤；不得用重复启动编辑器、反复重试写资产或反复要求录制代替定位。`ue_remote.py` 输出包含阶段和执行结果的 JSON；超时不表示编辑器端命令已被取消。

## 签收与续接

用户已签收的范围持续有效。只有相关代码/资产依赖变化、新故障或用户明确要求才重新验证；“继续”直接接未完成项，不重新询问已批准事项。

`current-status.md` 保存当前范围和本轮任务检查点。结束或中断时记录：已完成、剩余、相关证据、失败原因和下一步。历史证据保留在档案中；新检查不得替代未执行的 PIE/发布验收。只更新受本轮影响的条目，不复制全部历史方案。
