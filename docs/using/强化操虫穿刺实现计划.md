## 1. 已确定的玩法合同

| 项目 | 本招规则 |
|---|---|
| 名称 | 强化操虫穿刺；原生类、GA 和 Montage 使用 `KinsectPiercer`。 |
| 输入 | `RT+Y`，解析标签为现有 `Input.Weapon.RTY`。 |
| 派生来源 | 当前空中舞踏来源必须为 `EIGDanceSource::KinsectSlash`。按现有操虫斩规则，猎虫段 `[0]` 的真实伤害 GE 成功并提交舞踏后才形成这个来源；仅武器命中或落空不满足。 |
| 可派生时机 | 与空回、操虫斩相同：`Combat.State.Aerial.Falling` 在场时才允许。操虫斩舞踏的保护前段不允许；其现有 `IG Aerial Handoff` 到达后才开放。 |
| 三段判定 | `AttackSegments[0]`、`[1]`、`[2]` 各是一段独立武器判定，具体 `Attack Collision` 窗口由用户放置。每段对同一目标在本次激活内最多成功伤害一次。 |
| 判定窗口位置 | 用户可按动作实际接触安排在主 Montage 或落地 Montage；方案不预设“前两击一定空中、第三击一定落地”，也不写入猜测时间。 |
| 方向 | 在解析本次 RT+Y 输入时冻结准心射线，激活使用其**水平朝向**；镜头俯仰不改变本招曲线、距离、升高、下落速度或时长。 |
| 动作链 | `200` 起手 → `201` 空中穿刺过程 → **真实触地** → `203` 落地攻击/后摇。动画资源 `202` 用作 201 阶段的循环表现，不能当作第四个游戏运动段。 |
| 舞踏/精华 | 本招命中不增加舞踏、不重置空中预算、不点灯。空中武器段使用舞踏倍率；实际触地后的地面段按项目地面攻击规则结算。 |
| 生命周期 | 一个 ActionToken、一份攻击激活身份，跨空中/落地两条 Montage 保持。触地不立即结束 GA；203 的功能部分由本 GA 完成后再交回普通移动。 |
| 位移所有权 | 200/201：录制曲线；203 Over：直接 Montage Root Motion（2026-10-01 用户裁定）。 |

“同空回以及操虫斩”指本招的**入招门槛**，不是给 200/201 随意增加新的空中取消窗口。本招内部的地面连段/翻滚接受窗口在 203 中按现有通知体系配置。

### 2.1 数据来源和边界

原始录制是 `mhrise_20260930_163408_01_samples.csv`，路径由 `Scripts/MHRise/recorder_path.py` 定位，不在新脚本中硬编码某台机器的 Steam 盘符。该录制的第 8、23、31 次是疑似挤开样本，保留在全样本审计，不用于首版轨迹标定。

最新完整导出保留了原始世界轴位移与逐次时间，但其 `forward/right/up` 仍以 201 的**三维起始速度**建基。制作本招运行时曲线前必须按 §5 改成水平建基；不能把旧倾斜局部 `up_cm` 当世界高度直接导入。旧 201-only 文件只用于局部诊断。

本次只读检查的 36 条候选链中：

- 200 首末采样跨度约 `0.383～0.392s`；201 首末跨度约 `0.192～0.375s`，差异与触地截断有关。
- 203 有 32 条约 `1.567～1.575s` 的完整候选和 4 条提前离开该动作的短段。203 的自然后摇曲线只用完整候选，短段另用于验证接受窗口/取消。
- 201 起始方向的世界上向分量集中在约 `-0.343～-0.340`；这是本招自身向下的运动，不是把准心俯仰用作位移方向。
- 以上是采样跨度与筛选事实。生成运行时相位时长时使用**下一相位首帧时间减本相位首帧时间**，补齐边界间隔；不能把首末样本跨度直接当完整动作占用时长。

旧[真值表](../reference/真值表.md)和[操虫斩曲线](../reference/操虫斩曲线.md)的 200/201/203 汇总来自较早录制。它们用于来源追溯和动作序号，新的具体参数以本次重建审计为准。当前样本不支持把 201 的地面终点或整招总时间写成唯一常数。

### 4.2 来源的唯一真值与镜像

`URes_InsectGlaive::DanceSource` 是唯一真值。M2 已实现 `RefreshDanceStateTags()` 与 `FWeaponOwnedTagToken DanceSourceTagToken`，使用 `EWeaponTagOwnerKind::Resource` 记账：

1. `AddDanceStack(KinsectSlash)` 成功后，由 Resource 同步取得 `Combat.State.Aerial.Dance.Source.KinsectSlash`。层数已经满也必须同步；不额外要求 `DanceStacks > 0`。
2. 来源改为 `AdvancingCounter` 时释放 KinsectSlash 镜像，并同步对应已注册来源；资源数值与标签必须一致。
3. `ClearDanceStacks()`、运行时关闭、换武器同步释放。确认受击/死亡/收刀等既有清空合同会走到该入口，缺失的生产调用在 M2 补齐并测试。
4. 普通的 GA 完成/被后继 Superseded 不单独清除合法的 DanceSource；资源状态可以在来源 GA 自然结束后继续存在，到落地/清空时解除。

数值修改与标签同步必须在 `OnDanceStateChanged` 广播前完成，让观察者读到一致状态；初始化/卸载也直接同步或释放，不能只监听广播（关闭时既有代码会抑制广播）。清空时即使数值已为零/None，也要保证来源 Token 已释放，不能因提前返回留下镜像。

不能把来源写在新 GA 的 `GrantedTags` 中，也不能在操虫斩激活时就给；这会让未命中也能派生。不能把它作为源 Combo 边的短寿命标签来替代 Resource 镜像，否则 Superseded 清理会删掉新招正要读取的合法来源。

## 5. 水平锁向与完整曲线生成

### 5.1 锁向算法

使用 `FWeaponAbilityActivationContext.Input.Aim.Direction`，它来自 `CaptureAimSnapshot(Action)` 的**相机射线方向**。不使用角色位置到 TargetPoint 的三维向量；第三人称视差会把镜头俯仰间接带进方向。

```cpp
FVector D(Aim.Direction.X, Aim.Direction.Y, 0.0f);
D = D.GetSafeNormal();
if (D.IsNearlyZero())
    D = FVector(Input.ActorForward.X, Input.ActorForward.Y, 0.0f).GetSafeNormal();
LockedYawDirection = D;
// 原生只更新 Actor Yaw；Actor Pitch/Roll 和本招 VisualPitch 不由准心驱动。
```

冻结后不再跟随镜头、目标或摇杆。普通攻击基类默认的摇杆方向修正在本招覆盖；没有新 MotionWarping Target。进入本招时旧操虫斩的视觉俯仰由旧 Action 按现有 Superseded 合同退场，新招不取得 VisualPitch 所有权。

### 5.2 离线坐标与曲线口径

Rise 世界轴是 X/Z 水平、+Y 上向。对每次完整链，取 201 开始后的稳定**水平**运动方向：

```text
F = normalize(V201.x, 0, V201.z)
R = (F.z, 0, -F.x)
Delta = (WorldPosition - 本相位首帧位置) * 100
Local.X = dot(Delta, F)       # 前向 cm
Local.Y = dot(Delta, R)       # 右向 cm
Local.Z = Delta.y            # 世界上向 cm
```

相机俯仰只留在审计列，不参与分组、缩放、曲线旋转或任何参数回归。曲线的纵向量是世界竖直运动，包括起手抬升与后续向下穿刺；“忽略瞄准俯仰”不等于把 `Local.Z` 清零。

运行时 UE 坐标中，`D=LockedYawDirection`、`R=WorldUp×D`：

```text
WorldOffset(t) = D * Curve.X(t) + R * Curve.Y(t) + WorldUp * Curve.Z(t)
WorldVelocity(t) = 同一变换作用于曲线按真实秒数求得的导数
```

三份 CurveVector 横轴直接用**相位内秒数**，纵轴 cm；每条从 `(0,0,0)` 起，键时间严格递增。只要求时间有序与数值有限，不要求 X/Y/Z 单调，也不要求末位移回到零。由同一曲线或同一标定模型求终末切线，不能回读已经被源移除顺序影响的 CMC 尾帧速度。

主 Montage 结构：`Start200 → Dive201 → DiveLoop201`，最后一个 Section 自接至真实触地。运动相位始终叫 201；202 只是相应循环 clip。落地 Montage 为单个 `Landing203`，无自循环。201/202 的姿态衔接和 202 首末接缝需要 E1 目视及脚本姿势审计，文件名中的 Loop 不替代验证。

202 的循环表现由 `DiveLoop201` 的 **Section 自循环**承担（`NextSectionName = DiveLoop201`），三个 Section 一律保持 `LoopingCount = 1`。§8.1 的「循环次数由高度决定」是运行时的结果：201 时钟持续增长，动画一直循环到真实触地那一帧被本 GA 切走，飞得越高重复越多——**不按落地高度生成不同循环数的 Montage**，循环次数不写进资产。副作用要一并接受：主 Montage 因此不会自然播完、不会有 `OnCompleted`，落地退出全部由运行时按 §6.3/§6.4 决定（与 §9.2「201 多次视觉循环」用例一致）。

**这是项目里第一次用 Section 自循环**：现有生成器都把最后一个 Section 的 `NextSectionName` 设为 `None`（操虫斩 `MHGZM5KinsectSlashAssetSetupCommandlet.cpp:258` 的 `Miss188`），段级循环则一律靠 `Segment.LoopingCount` 且恒为 1（`MHGZM5KinsectSlashAssetSetupCommandlet.cpp:186`；AirDodge 样板还把它乘进段长换算，`MHGZAirDodgeMontageSetupCommandlet.cpp:140`）。因此 M3 生成后必须回读 `CompositeSections[2].NextSectionName == "DiveLoop201"` 写进 JSON，并在 E1 目视确认它真的在循环——自循环要是没生效，主 Montage 会播完停住而 GA 仍在运行（本招 override 了 `StartAttackMontage`、不挂基类终止绑定，所以不会“播完就结束”，只会静默卡住）。

### 6.3 触地与结束顺序

1. 在确认的可行走地面接触上捕获真实 `HitResult`，设本招 Landing 锁存，立即关闭空中碰撞窗口并停掉 201 的曲线租约。侧墙、敌人 Hitzone 接触不是落地事件。

### 6.4 两条 Montage 的回调合同

现有 `UMHGZAttackAbility::StartAttackMontage()` 将 `OnInterrupted/OnCancelled` 绑定到基类 `OnMontageInterrupted()`，默认会 `RequestEndAction(Interrupted)`；该中断方法不是可供本招直接 override 的虚方法。因此不能只写“停止主 Montage 再播放落地 Montage”，也不能假定默认绑定会保留 GA。

采用当前操虫斩的专用 MontageTask 模式：本招 override `StartAttackMontage()`，自行创建空中任务并绑定本招的主阶段完成/中断回调；落地任务绑定独立的落地阶段回调。两条任务都保留 ActionToken、相位和准确实例身份，**不追加基类默认终止绑定**。

- 在 201→203 切换中的任何 `EndTask/Montage_Stop` 前设置 `bSwitchingToLanding` 和 Landing 锁存，解绑旧任务的委托，注销旧实例。停止操作可能同步回调，不能在它之后才设置标志；普通取消/EndAbility 不伪装成落地切换。
- 旧主任务因真实触地被停止属于预期阶段切换：该 Completed/Interrupted/Cancelled 不得结束 GA、退款、清 ActionToken 或重设物理。既有攻击 GUID、激活级命中集合、成本与动作锁保持；只关闭旧实例的窗口。
- 注册并验证新 Over 实例后才结束切换事务。若创建/播放/注册失败，按异常中断清理整个本招，不能留下只有移动、没有合法表现的 Action。
- 正常运行时，只有当前相位/当前任务的意外中断才能结束 Action；过期主实例回调一律无效。当前 Over 自然到末尾即结束；当前 Over 被合法新动作接管则走 Superseded，不误判为需要重播落地。
- 添加生产回调测试：触地切换触发同步旧中断，GA仍存活且只播一次203；延迟旧完成/中断不影响新实例；当前203意外中断能清理；落地Montage启动失败能完整清理。不能仅用一个静态阶段布尔值替代这些真实任务/实例用例。

## 8. Montage 通知、播放速度和用户操作

### 8.1 生成器负责的内容

保持操虫斩当前规范的轨道组织：

| 通知轨道 | 内容 |
|---|---|
| `Attack` | **留给 E1 用户摆三个 `Attack Collision`**；生成器只建轨、不写窗。若三个窗在时间上拥挤，增加 `Attack_1`/`Attack_2` 作为排版轨道，ConfigIndex 仍是判定身份。 |

源动画存在半速导入历史。生成器回读 `GetPlayLength`、序列 `RateScale`、Segment `AnimPlayRate`、Montage/GA 播放率，按下式对齐实际运行时长：

```text
RuntimeSegmentSeconds = SourceRangeSeconds /
    (SequenceRateScale * SegmentAnimPlayRate * Montage/GA实际播放率)
```

200 与 203 用新的相位真值校准；201/202 用实际正常动作节奏校准，**202 的重复次数由真实触地时刻决定（§6.2 的 Section 自循环），不烘成有限循环数**。Montage 能直接设置正确 Segment 速率，不要求为了本招额外烘焙 2x 资产。若确实需要新派生序列，继续按现有 `_2x`/`_IP` 后缀和 `Generated` 目录约定输出，并确保位移/Root Lock 正确。

命令行生成器的写入开关用三段式：**裸跑拒绝运行（非 0 退出）+ `-AuditOnly` 只读 + `-Apply` 显式写入**，裸跑不得退出 0 冒充已生成。写入只更新本招拥有的 Slot/Segment/Section/播放率/Root Lock 与 GA/DA/Combo 引用，**不创建、不删除、不移动用户通知**；重跑后逐条回读 `Event.Guid`、`NotifyName`、`TrackIndex`、`GetLinkMethod()`/`EndLink` 与 `AnimNotifyTracks[i].TrackName` 并写进 JSON，任一条不一致就不保存任何 package。**不得重建或清空用户已经摆好的 AttackCollision、Combo/Dodge 窗口、通知 GUID 与轨道**。要改用户窗的时间只能在原事件上就地改，不能删掉再用 `AddAnimationNotifyStateEvent` 重加（会换掉 `Guid`）。曲线重标定也不能改碰撞时机。

### 11.2 四处按实现改写口径的地方

- **`CanActivateAbility` 不读 `GetIGResourceComponent()`。** 它是引擎在 `SetCurrentActorInfo` **之前**就会调的纯查询，而 `GetIGResourceComponent()` 经 `GetAbilitySystemComponentFromActorInfo()` 读 `CurrentActorInfo`。改为直接问 Host 的 `ResourceProvider`（`ResolveResourceFromASC`）。这是自动测试发现的生产 bug，不是测试脚手架问题。
- **空中相位跑完不撤租约、不动模式。** 任务观察到「已完成」必然晚于本次物理更新：这里若改回 `MOVE_Falling` 就会在起手段与下潜段之间空出一帧自由落体，撤掉租约同样把同一帧剩余物理更新让给 `Super::PhysFlying`。两项都改成由下一个相位（同一调用栈里同步装上的租约）或任务收尾时再决定。
- **201 的覆盖时长没有曲线上限。** 它是被录制时的触地截断的结果，飞得更高就必然走出覆盖；按时长收尾会把胶囊冻在半空。终止条件只有真实 `ProcessLanded` 或独立看门狗，`IntegrateTerminalModel` 负责在那之前的续行。
- **入招那一帧必须放掉 `Combat.State.Aerial.Falling` 许可**（`PrepareAttackMontage`，已 Commit、蒙太奇未起播）。§6.2 的 Start200 行本来就写着这句，实现里漏过一次，一次独立复核把它连同两个后果一起翻了出来：
  1. **空回能在下潜中途把本招顶掉。** 空回的闸门是「Falling 在场 + 无 `CantDodge`」，而舞踏提交时 Host 会把 `CantDodge` 与 `CantAttack` 一起退掉。本招的「攻击锁」（`Attacking`/`BlockMovement`/`CantAttack`）**不拦**空回 —— `HasPlayerActionInputLock` 只看 `Sheathing`/`Dodging`，所以 Falling 才是承重的那一道。不放它，§1「200/201 不开放空中取消窗口」就是空的。
  2. **真实触地会播系统落地表现。** 本招刻意不挂 `IG_AerialHandoff`（§6.4），没有别人会停掉系统托管下落的表现会话；留着它，`Host::HandleLanded` 会按「系统托管下落结束了」播系统落地表现 —— 把水平速度重设成 337 cm/s 覆盖 203 的 authored 减速（§6.3.2 明令禁止），而且它 `Montage_Play` 的默认 stop-all 会顺手停掉本招自己的主蒙太奇。常见入口不是边角：操虫斩舞踏收尾时 `CompleteSlashAction` 就会起一段系统下落。
  中止滞空不需要在这里回领：基类 `UMHGZInsectGlaiveAbility::EndAbility` 在「取消 + 未接地 + 无其它已注册动作」时会领回，测试同时钉住了「入招时确实放掉」与「被打断后确实领回」两侧。
