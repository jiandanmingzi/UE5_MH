### 1.2 覆盖优先级

1. **基本覆盖：** 武器空挥有声；真正命中有声；多段攻击每个实际音效动作正确播放。

1. **覆盖对象：** 当前可执行的虫棍地面/空中攻击、实际特殊入口、连续多次挥击、操虫动作中的武器挥动；同招Entry/Core/Over及取消、跳Section、循环路径分别核对。仅文件存在的闲置GA/旧Montage不自动扩成待办。

| 项目映射 | GA或Host表现归属、Montage、Section/实际入口、音效事件键、点通知时间、声音类别、源组件、Socket、附着/瞬时位置、音量/音高、最终Sound包；武器声显式区分棍尖/棍尾 |
| 证据 | 解析定位、试听结论、必要的录制依据，标记“原作对应/通用复用/项目替代/待确认” |

一个媒体可被多招复用，一招也可由多层媒体组成，不能强行一对一。UE时间以当前Montage实际秒数为准，结合裁切、入口和播放倍率换算；不能把原动画第N帧或原作动作序号直接当UE音频触发时间。

提取文件仅作为本地研究/项目制作素材，不把完整银行、批量原始WEM或游戏资源库提交/推送。最终派生音频也不能默认视为可公开分发；对外发布/推送前另行确认资源使用权限。本次版本检查点未包含这些音频。

## 5. 播放链路设计

### 5.1 动画同步短音：点通知决定时机，配方决定位置

```text
实际播放的Montage声音点通知（事件键、音源、位置及混音配方）
  → 攻击：精确本次GA动作实例；通用落地：实际Host表现实例
  → 按声音类别解析已加载音源；武器覆盖不串入地面声
  → 武器棍尖/棍尾附着播放，或地面接触点瞬时播放
```

- 新增通用、无运行时可变状态的攻击音效Notify；Notify不是播放状态所有者，不缓存某角色/GA的指针，不修改共享Sound字段。
- 普通身份继续使用GA的`AudioIdentityTag`；多次挥击用子事件键/明确索引区分。武器覆盖优先匹配具体键，再匹配动作级默认；未配置则使用对应段`SwingSound`。没有声音时安全跳过并只报告一次缺项，不阻止攻击。
- 武器覆盖为软引用时，在装备/动作资源准备阶段预加载并由运行时持有；Notify及命中回调不临时同步加载磁盘音频。尚未就绪则使用已加载兜底，不暂停动作等待声音。
- 音效事件独立于伤害段：同次挥击可以有两个伤害判定而只响一声；反过来，一个持续伤害段也可以有多次真实挥击。映射表显式记录事件与伤害段关系，不自动每帧或每次碰撞开窗播风声。
- 运行时只对匹配的实际动作实例响应。预输入未提交、被拒绝的GA和没有播放的Section不能提前发声。跳Section不补播被跳过的声音；正常循环重新经过Notify可以再次触发，不做“整场只响一次”的去重。
- 快速连段、内部序列切换与惯性混合按实际播放位置触发，不能用GA激活时的固定Timer串代替Montage时钟。
- 短挥击为单次声音，可自然衰减；持续蓄力/旋转/虫翼循环由当前运行时持有AudioComponent，退出Section、GA取消、换武器、销毁时必须停止并释放，不能只依赖NotifyState.End。
- 武器声音点显式选择`IG_FrontTip`或`IG_RearTip`，不得默认全部挂武器原点；扬尘/落地/翻滚使用地面接触位置。通用动作通知与缺挂点处理已按1.22落地；不为音效增加影响碰撞的组件或改变骨骼挂点。
- 扬尘使用1.30的 `GroundDust` 事件通知，向Host广播地表位置/法线后触发可选声音；未来粒子独立订阅，不把音源存在当作特效事件的前提。落地、衣服晃动仍使用独立声音通知；衣服声不走武器挂点，未确认的装备声不自动填入该类。
- 精华交付已改为实际回手手臂挂点的短空间声；其它UI提示路径保留，交付时机和命令去重不改，不改成蒙太奇点灯。猎虫持续声仍由自身状态管理。

三灯增强若在素材中确有独立层，放在同一次挥击的声音选择/叠层阶段，而不是再保留GA激活时无条件额外播放。普通招式读取资源权威状态；会消费灯的觉虫击读取已经冻结的本次消耗快照，不因消费后标签消失而误选无灯声音。不得为音效伪造三灯资源Tag或改变GE。

### 5.2 命中：由既有结算后Cue触发

```text
现有攻击/猎虫/粉尘结算
  → AttributeSet已有命中反馈
  → HitFeedbackRouter已有ExecuteGameplayCue
  → Weapon真实接触：GCN_Hit_WeaponSound → 真实ImpactPoint的一层短主音（已实现）
  → 物理/元素/暴击Cue：各自视觉/未来附加层，不再各放同一主音
  → Kinsect / IG.Powder等：各自专用声音（未接入）
```

- 已新建可执行的武器主音Cue及常驻资产。即便GA段`HitCueTag`缺省或为专用视觉Tag，主音也由真实Weapon来源单独分发，不批量改GA段；猎虫及聚爆等专用音效未来沿用各自配置入口。
- 第一版不另加全局命中总线，不绕开Router，不在伤害通知、猎虫Actor和Cue三处重复播同一次接触声。
- Cue从EffectContext读取来源/动作/伤害类型；不改动作值、肉质、暴击及粉尘公式来获得声音分类。不因参考表里写“打击”就顺便修改当前玩法伤害类型。
- 一次命中以一层主接触声为基底，属性/暴击有素材时才叠加短附加层，不让三个Cue各播放一份完整相同主音。
- 不按`AttackInstanceID`整招去重：同一GA的多段、多目标、贯通连续命中必须各有反馈。沿用已成立的命中去重；声音并发用于控制拥挤感，不反向吞掉真实伤害。
- 多粒粉尘同帧引爆可用声音并发/音量聚合控制叠响，但不得减少粉尘结算、改变爆炸范围或按主观听感合并伤害段。
- 命中声初始位置取真实接触点；短音不默认永久附着高速移动目标。未知表面提供通用斩击/打击兜底；后续材质选择走可配置数据，不硬编码训练木桩类名。

### 5.3 导入和混音约束

保留原始解码WAV；只在导入副本做必要裁空白、声道和增益处理，不剪掉真实起音，不把所有素材峰值强行归一到同一响度。保留需要的尾音和循环点；循环与一次性段分开配置。

建立独立的武器挥击、主命中、猎虫和粉尘并发设置，避免贯通/聚爆叠加削波。衰减、基础音量、变体权重和随机音高范围均为编辑器可调值，首版不写无依据的原作数值。3D声道方案先试听验证，不能将保留的立体声素材盲目当成精确点声源。

1.20时仍共享挥击衰减；1.22已分别配置猎虫、动作与精华的衰减/并发。用户此前提出的猎虫过响、地面声/精华偏弱偏闷及扬尘未听到仍须新版本局部听感确认；不能只改响度或用技术检查就标为听感修复。

声音和已存在卡肉/慢放时钟分别管理；不为了让声音对齐而增删卡肉。正常速度是主要听感验收，慢放只辅助检查事件时刻，不要求把声音机械拉长成0.2倍速。
