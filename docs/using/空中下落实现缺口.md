## 1. **空中回避 `137` 完全没有实现**（最大的缺口）

**现状**：GameplayTag `Combat.State.Aerial.Falling.IG_AirDodge` 在
`Config/DefaultGameplayTags.ini:64` **有定义**（注释还写着「空中回避后下落」），
但**全工程零引用** —— `grep -rn "IG_AirDodge" Config/ Source/` 只命中 ini 那一行。
也就是说这条路径目前根本没有代码。

**真值**（`下落物理.md` 第三节）：`137` 是一个**纯抛体** ——

| 量 | 实测值 | 依据 |
|---|---|---|
| 重力 | **−2378 cm/s²**（= `AerialFallGravityScale`，差 0.08%） | 219 段，**R² 中位 0.9991**，219/219 段 R²>0.98，IQR 只有 4 cm/s² |
| 初速（水平） | **900 cm/s，方向恒为朝向** | 段内 894 → 900，方向−朝向中位 0.000° |
| 初速（垂直） | **+1182 cm/s** | 段首 vy 中位 |
| 总时长 | **142 帧 / 1.185 s** | 156/219 段精确 142 |
| 净位移 | **水平 1065 cm / 垂直 −267 cm** | |

**正推验证**（改完拿这组数自检）：用 v₀=(900, +1182)、g=2378 推 —— 顶点第 **59.5** 帧
（实测 vy 过零在第 57 帧 ✓）、峰值 **+293 cm**、142 帧后净落 **−271 cm**（实测 −267 cm ✓）。

**要做的**：加一条 `BeginAerialFalling(/*bEnhancedVariant=*/false, …)` 的调用路径
（空回与白灯无关，实测无/有白灯的真值**完全相同**），并在进入时施加上述初速。

**⚠ 但要注意**：初速**不是** `BeginAerialFalling` 该做的事 —— 那个函数只写物理参数
（重力 / 刹车）。初速属于「动作本身」，应当在上一个动作（起跳 / 撑杆跳弧 /
被打断的动作）结束时就装好。**先确认 137 的入口由谁负责**，再决定初速装在哪。

**验收判据**：PIE 里做一次空回，`Saved/RuntimeTelemetry/*/Character/Spatial.csv` 的
`vZ` 应从 **+1182** 起、以 **−2378 cm/s²** 匀减，142 帧后净落 −267 cm、水平净移动 1065 cm。

## 2. 落地**重设**水平速度，现在做的是摩擦衰减

**现状**：`HandleLanded()`（`MHGZWeaponRuntimeHostComponent.cpp:915`）**不写 `CMC->Velocity`**，
落地后水平速度靠 `FallingLateralFriction` 摩擦衰减到 0。引擎侧遥测实测：
落地帧 `v2D` 292 → 126 → 24 → **0**（4 帧到静）。

**真值**：`148 起跳落地` 的**首帧**水平速度**恒为 337 ± 6 cm/s，与入速完全无关**
（`下落物理.md` 第六节）：

| `148` 的前驱 | n | 入速中位 | `148` 首帧中位 | 比值 |
|---|---:|---:|---:|---:|
| `157` 下坠 | 227 | 859 | **336** | 0.392 |
| `137` 空中回避 | 33 | 898 | **338** | 0.376 |
| `143` 起跳下坠 | 134 | 314 | **338** | **1.075** |
| `156` 白灯弧 | 45 | 306 | **336** | **1.101** |

**入速 306 也变 337、入速 898 也变 337**（入速↔落地首帧的相关系数 **r = +0.086**）。
⇒ 是**重设**，不是衰减。（这条同时解释了此前看起来「矛盾」的 0.379 与 1.125 ——
那是同一个常数从两侧看。）

**要做的**：落地时把水平速度设成 ~337 cm/s（方向保持），之后才交给落地动画的摩擦。

**验收判据**：以两种入速（约 300 与约 900 cm/s）各做一次落地，量 `148` 首帧的 `v2D`，
两者都应落在 **337 ± 6**。

## 3. `188` 操虫斩结束需要**第三个重力常数**（配置里没有）

**真值**：`188` 的 g = **−3101 cm/s² = 3.16 g₀**，61 段、**R² 中位 0.991**、55/61 段 R²>0.95
—— 是干净的恒定重力抛物线，**不是**两段式。比普通空中重力（2.42）强 **30%**。

项目现在只有两个重力常数（2.4246 / 2.5740），**没有任何一个能配 `188`**。
按现在的代码，操虫斩落空后会用 2.4246 下落，**下坠速度比原游戏慢约 30%**。

**要做的**：在 `InsectGlaiveCombatConfig` 加一个（例如 `KinsectMissFallGravityScale ≈ 3.165`），
由 `188` 的入口传入。

**顺带**：`188` 也是**唯一水平速度会衰减的下坠段**（逐段比值中位 **0.859**，即段内衰减约 20%）。
`BrakingDecelerationFalling` 目前是 0，所以要复刻这一条还需要一个横向阻力项。
**原因未查清**，先记为待办。

## 4. `DA_IG_Combat` 把三个值**钉住**了 —— 改 C++ 默认值不生效

`Saved/AssetProbe/m5_assets.json`（2026-09-16 探测）显示 `DA_IG_Combat` **序列化**了
`AerialFallGravityScale = 2.4245998` / `WhiteAerialFallGravityScale = 2.5739998` /
`AerialFallBrakingDeceleration = 0.0` —— 就是类默认值，**没有覆盖**，但资产会把它们钉住。

⇒ **以后改 `InsectGlaiveCombatConfig.h` 里这三个默认值，运行时不会生效**，必须同时改资产。
（`aerial_fall_max_seconds` 不在探测列表里，走类默认。）

**要做的事**：加新常数（如第 3 条那个）时，**要么**加进 `DA_IG_Combat` 的探测与序列化，
**要么**确认它不受已存在资产的钉死影响。

## 5. 两条已核对**无需改动**的，别再回头查

1. **`AerialFallMaxSeconds = 4.0` 只是看门狗**，不是物理钳制（超时只做「恢复物理 + 停表现 +
   释放 tag + `SetDefaultMovementMode()` + Warning」，**不修正位移**）。
   真值侧下坠段中位只有 28 帧（`143`，0.234 s）/ 22 帧（`157`），离 4 s 极远。
2. **白灯分支的两个调用点是对的**：`MHGZBackVaultAbility.cpp:271`（白灯后撑杆跳）与
   `MHGZAdvancingCounterAbility.cpp:95`（舞踏，恒 true）。实测 `156` 白灯弧 = −2517
   （≈ 2.5740×980）验证了前者。
