## 6.5 空中交棒有**一帧无蒙太奇**的姿势空档（2026-09-23 新发现；22:50 按撑杆跳配方重做）

**现象（用户 PIE 目视「下坠途中顿一下」的真身）**：空回 `137` 蒙太奇自然播完 → **下一帧没有任何蒙太奇实例**
（`GA_IG_AirDodge` 仍活跃，`ActiveMontage` 为空）⇒ 该帧姿势由**底层图（MM）**驱动，接着下落蒙太奇
`AM_IG_AerialFall_W` 才从 **0.5 权重**混两帧到 1.0。录制 `20260923-211851` 帧 2416–2420 实测权重：
`1.0 → 0.24 → （无实例）→ 0.5 → 1.0`。

**量化**：`MeshBoundsZ − LocationZ`（姿态相对胶囊高度）在缝前/缝后都稳定在 **−17.5 cm**，
中间三帧塌到 **−30.5 / −33.4 / −28.1**（深 ~15 cm）再弹回 —— 是**过冲**而非换姿态；
同窗口里胶囊 `LocationZ`/`VelocityZ` 完全弹道、水平与 `ActorYaw` 平滑 ⇒ **胶囊无顿挫，顿挫在姿态层**。
对照组（无关本轮的开关）同帧完全同型 ⇒ 既存缺陷。

**与速度那条的关系**：速度归零（§7，已由窄门控修掉）与本条是**两个独立缺陷**，观感由本条主导
（用户实测：修速度后顿挫仍在）。**不要用改弹道/改速度去治本条**（`空回P0-P1完整修复方案.md` §E 的边界）。

**参照实现：撑杆跳的弧段→下坠交接（用户提出，语料库验证通过）**

| | 撑杆跳（`QianChengGanTiao_Over` → `AerialFall`，~100 次同型） | 空回（`AirDodge` → `AerialFall_W`） |
|---|---|---|
| 交接前一帧 | 弧段 `w=1.00`（部分样本里下落实例已 `w=0.00` 存在 ⇒ **提前一帧起播**） | 空回 `w=1.00` |
| 交接帧 | **弧段 `w=0.50` + 下落 `w=0.50`（同帧交叉）** | 空回 `w=0.24`（淡出） |
| 下一帧 | 弧段 `w=0.00` + 下落 `w=1.00` | **（无蒙太奇）** |
| 再下一帧 | 下落 `w=1.00` | 下落 `w=0.50~0.67` |
| 姿势偏移（`MeshBoundsZ−LocationZ`） | −20.4 → −20.8 → **−20.9** → −21.2 → −21.6（**±1 cm，平滑**） | −17.3 → **−33.5** → −25.5 → −18.1（**15 cm 下陷再弹回**） |

代码层的差别（同一件事的两种触发方式）：撑杆跳在**自己的收尾逻辑**里调
`Host->BeginAerialFalling(...)`（`MHGZPoleVaultAbility.cpp:428`，注释：CurvedVault 正常收尾时已切 Falling）
⇒ 下落蒙太奇在弧段仍有权重时起播；空回在 **`EndAbility`** 里调
（`MHGZAirDodgeAbility.cpp:607`），而 `EndAbility` 由**自然播完回调** `HandleAirDodgeVisualCompleted`
触发 ⇒ 落在蒙太奇死后的那一帧。

**代码层的差别（2026-09-23 22:50 定名，这才是真因）**：不是「谁先调 `BeginAerialFalling`」——
两边都在 `EndAbility` 里调，两边也都有同一行 `if (!finished) Montage_Stop(0.05f)`。真因是
**蒙太奇实例在收尾那一帧还在不在**：

| | 撑杆跳弧段 `*_Over` | 空回 `AirDodge` |
|---|---|---|
| `bEnableAutoBlendOut` | **false**（`PlayVaultMontage` 里显式设，注释写明「两种情形都不要改成 true」） | true（默认，旧代码的注释还专门解释为什么「特意不动」） |
| 到自身长度时 | **不终止**：`bPlaying=false`、位置夹在 `长度−5e-5`、权重保持 1.0（引擎 `FAnimMontageInstance::Advance` 把整段自动淡出交给 `bEnableAutoBlendOut` 把关；`Terminate()` 只在 `IsStopped() && Blend.IsComplete()` 时发生 ⇒ 关掉之后 `OnMontageEnded`/`OnCompleted` 永远不来） | 自动淡出 → `Terminate()` → `OnMontageEnded` → `OnCompleted` |
| 收尾触发点 | **自己的移动源**（`HandleBackVaultMovementFinished → RequestEndAction(Normal)`） | 就是这条蒙太奇的自然播完回调 |
| `EndAbility` 那一帧 | 实例**还活着**，`Montage_Stop(0.05f)` 是一次真淡出 ⇒ 与下落蒙太奇**同帧交叉**（弧段 1.00→0.50，下落 0.00→0.50） | 实例**已经没了**，`Montage_Stop` 是空操作 ⇒ 一帧无蒙太奇 |

实测对照（同一台机、40 Hz：`20260923-194246` 帧 2882–2885 vs `20260923-211851` 帧 2414–2418）：
撑杆跳 `w=1.00` → **`0.50`+下落 `0.50`** → `0.00`+`1.00` → `1.00`；空回 `w=1.00` → `0.24` → **（无）**
→ `0.50` → `1.00`。前者的弧段位置在 `1.1029` **冻住保持**（= 该蒙太奇长度，`Saved/_aerial_handoff.json` 可查），
后者一路淡到消失。

**修法（2026-09-23 22:50 按撑杆跳配方重做；此前的「提前一帧」版已按用户要求清掉）**

两处，都在空回侧，都在 `UMHGZAirDodgeAbility::StartAttackMontage` / `EndAbility`：

1. **关掉自动淡出**：`MontageInstance->bEnableAutoBlendOut = false` —— 与 `PlayVaultMontage` 同一行、
   同一个理由。终末姿势保持住，收尾那一帧实例还活着。
2. **收尾触发点不变（仍是蒙太奇自身长度 1.18333 s），但改由任务按位置上报**：
   `ReportCompletionAtMontageEnd()` + 纯判据 `HasMontageReachedEnd(Position, PlayLength)`
   （容差 1e-3 s > 引擎末尾夹取 `长度−5e-5`，且窄于一帧两个数量级）。它走的是**同一条收尾路径**
   （`HandleAirDodgeVisualCompleted → TryFinishAirDodge → EndAbility → BeginAerialFalling`），
   只是信号源从引擎的 `Terminate` 换成「位置已到长度」这个事实。
3. **`EndAbility` 里那行 `Montage_Stop(0.05f, ActiveAttackMontage)` 去掉守卫**（原来 `if (!bAirDodgeVisualFinished)`）：
   撑杆跳那条守卫在本招是错的 —— 本招的「视觉完成」那一刻实例还活着并保持终末姿势，**正是要淡出的对象**；
   漏掉它实例会以 1.0 权重留在槽里跟下落蒙太奇抢姿势。停一条没在播的蒙太奇是空操作。

⚠ **不要跟地面翻滚（`UMHGZDodgeAbility`）对齐**：它显式设 `bEnableAutoBlendOut = true`，理由写在自己的注释里
（「没有保持终末姿势等交棒这一步，必须在末段自己结束并释放动作锁」）。空中这一条正好相反 —— 它的收尾**就是**一次交棒。

**一眼可验的现场读数**：`Animation/MontageInstances.csv` 的 `EnableAutoBlendOut` 列（第 16 列）读的就是
